2. DMARC处置策略新增"进行下一步"选项

2.1 方案概述

修改前，DMARC 的处置策略枚举为 ['reject', 'discard', 'quarantine', 'audit']（4 项），不含 accept。SPF / DKIM / PTR 的 PROTOCOL_ACTIONS 包含全部 5 项（含 accept）。本次将 DMARC_ACTIONS 扩充为与 PROTOCOL_ACTIONS 相同的完整五项集合，使 DMARC 支持「进行下一步」处置策略。

accept 的语义为：当邮件命中该 DMARC 条件行时，不做阻断 / 隔离 / 标记，直接传递给流水线下一检测节点（PTR 或下一模块）。适用于管理员希望对特定 DMARC 条件（如 p=none、DMARC无记录）采取宽松策略的场景。

字段修改前修改后
DMARC_ACTIONS 枚举 ['reject', 'discard', 'quarantine', 'audit']（4 项） ['reject', 'discard', 'quarantine', 'audit', 'accept']（5 项）
新增选项短名 — 进行下一步（authSpoofing.protocolActionShort.accept，key 已存在）
新增选项描述 — 不做处理，传递给下一个协议检查（authSpoofing.protocolActionDesc.accept，key 已存在）
下拉选项数量 4 项 5 项
修改文件 src/components/security/auth-spoofing/ProtocolChecksSection.tsx（DMARC_ACTIONS 常量，第 37 行）
i18n 变更 无需新增 key。accept 对应的 protocolActionShort.accept（进行下一步）与 protocolActionDesc.accept（不做处理，传递给下一个协议检查）在 messages/zh.json 中已存在。
