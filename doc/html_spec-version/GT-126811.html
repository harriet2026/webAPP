灰名单从执行动作中分离

路由：/zh/rules/rbl  ·  组件：rbl-config-serde.ts、RBLFilterPage.tsx  ·  变更类型：架构变更  ·  2026-07-31

1.1 方案概述与架构说明

原设计中 greylist 是 product_action 的一个枚举值，与 block / quarantine / mark 并列在同一个 Select 下拉中。用户反馈：灰名单是"临时挂起等待重试"的处置策略，而其他选项是"即时处置动作"，两者语义层不同，不应混放。

最终实现方案：在 RblConfig 中新增独立的 greylistEnabled: boolean 字段，与 action: RblImmediateAction 并列。RblImmediateAction 类型不再包含 'greylist'。保存时 diffRblConfig 根据 greylistEnabled 决定写入 API 的 product_action 值（greylistEnabled=true 时写 'greylist'），保持后端接口兼容。

路由：/zh/rules/rbl  ·  组件：RBLFilterPage.tsx  ·  变更类型：交互优化  ·  2026-07-31

2.1 方案概述

原双列并排布局（grid grid-cols-2 divide-x）视觉上暗示两列可同时启用，但 API 层两者互斥。用户指出此设计会造成歧义。

变更 1 · 域名类型输入控件：下拉 Select 改为可自由输入 Combobox + 租户接收域名建议列表

1.1 方案概述

原实现（GT-12117）中，新建/编辑规则抽屉的"发信人"字段在类型为"组织域名"时，仅允许从当前租户的接收域名列表中下拉选择。 当租户无接收域名时，控件显示提示文案"该租户暂无接收域名"且无法输入，导致无法针对外部恶意发信域名（如 phishing-attack.com）创建黑名单规则。

本次变更将该控件从纯 Select 改为内联 DomainCombobox 组件：支持自由输入任意合法域名，同时在输入框 focus 时将租户接收域名作为快捷建议展示在浮层中，建议项随输入词实时过滤。 i18n key senderType_domain 从"组织域名"更名为"发信域名"（更准确表达语义），新增 domainSuggestions 用于建议浮层标签文案。

修改位置：src/components/security/sender-filter/SenderFilterDrawer.tsx — 新增内联 DomainCombobox 子组件，替换 domain 分支下的 Select/空态提示； messages/zh.json 和 messages/en.json 更新 senderType_domain、senderPlaceholder_domain，新增 domainSuggestions。
