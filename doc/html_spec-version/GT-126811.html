灰名单从执行动作中分离 — 两段式布局

GT-12682 · 2026-07-31 · 变更

1.1 背景与目标

原设计中，greylist 作为 product_action 的一个枚举值与 block / quarantine / mark 并列放在同一个 Select 下拉框中。用户反馈此设计存在语义混淆：灰名单是"临时挂起策略"（SMTP 451 DEFER），与即时处置动作（5xx REJECT / 隔离 / 标记）属于不同维度的概念，不应并列。

本需求目标：将灰名单策略从执行动作 Select 中抽离，作为独立区块，拥有自己的开关和配置入口。

1.2 变更范围

仅修改 RBL 过滤模块的处置配置区，不涉及其他功能模块（服务器列表、超时设置、灰名单配置弹窗等保持不变）。

1.3 Serde 层变更

文件变更内容说明
rbl-config-serde.ts 新增 RblImmediateAction 类型（'block' | 'quarantine' | 'mark'）；RblConfig 新增 greylistEnabled: boolean 字段 greylist 从 action 枚举中移出，改为独立布尔字段
rbl-config-serde.ts parseRblConfig 增加旧数据兼容逻辑：后端 action=greylist 转换为 action=block + greylistEnabled=true 保证历史存量配置正确读取，不影响 API 约定
rbl-config-serde.ts diffRblConfig 在 greylistEnabled=true 时向 API 写入 action='greylist'，保持后端兼容 API 层 payload 结构不变，前端 state 语义与后端协议解耦

1.4 UI 变更：两段式布局

区域变更前变更后
处置配置区 单个 Select 下拉，四个选项：阻断 / 隔离 / 标记 / 灰名单（混合并列） 上半区右列保留超时设置；下方 border-t 分隔后新增独立"灰名单策略"Section（含开关 Toggle 和配置摘要行）
执行动作区 包含 greylist 的 4 选 Select 3 选 RadioGroup（block / quarantine / mark），帮助 Tooltip 内联
灰名单策略区 不存在（灰名单作为动作选项隐藏于 Select 内） 独立 Section，含标题"灰名单策略"、副文案、Toggle 开关；开启后展示摘要信息与"点击配置"按钮

处置策略改为互斥卡片选择器 — 执行动作与灰名单策略并排二选一

GT-12682 · 2026-07-31 · 变更

2.1 背景与目标

需求点 1 完成后，执行动作与灰名单策略被拆为两个独立 Section，但并排双列的视觉样式暗示"可以同时启用"，而实际上两者在 API 层互斥（product_action 只能有一个值）。用户反馈：选择了执行动作后就无法配置灰名单策略，交互体验令人困惑。

本需求目标：通过 UI 明确表达互斥关系，同时保留两者各自的深度配置能力。

2.2 设计决策

采用"处置策略选择器"方案（RadioGroup + 可选卡片）：两张并排等宽卡片，选中态高亮边框，未选中态 dimmed（opacity-60），切换时自动展开该卡片内的配置控件。
方案描述决策结果
方案 A（已实现，需求点 1） 两段式：上方执行动作 RadioGroup，下方灰名单 Section+Toggle 已替换 未体现互斥关系
方案 B（平铺双列） 两列并排，左列执行动作 Select，右列灰名单 Toggle 已替换 视觉暗示可同时启用，与 API 约束矛盾
方案 C（本次采纳） 处置策略 RadioGroup + 互斥可选卡片，选中卡片高亮展开子配置 已采纳

2.3 UI 结构

区域内容交互行为
区域标题行 文本"处置策略" + HelpCircle Tooltip（说明互斥含义） Tooltip 悬停显示：rblFilter.disposalStrategyDesc
左卡片：执行动作 标题 + 副文案 + RadioGroupItem + 选中时展开 Select 下拉 点击卡片任意区域 → 选中执行动作策略；Select 阻止冒泡，避免切换策略时干扰动作值
右卡片：灰名单策略 标题 + 副文案 + RadioGroupItem + 选中时展开摘要行和配置按钮 点击卡片任意区域 → 选中灰名单策略；配置按钮点击需 e.preventDefault() 避免卡片 label 重触发

'greylist' true dimmed（opacity-60）；Select 隐藏 高亮（border-primary bg-primary/5）；摘要行可见

执行动作集合调整 — 拒收/隔离/审核/丢弃，移除阻断和标记

GT-12682 · 2026-07-31 · 新增移除

3.1 背景与目标

在需求点 2 的基础上，用户对执行动作的枚举值提出以下调整要求：

  • 移除 block（阻断）→ 改名为 reject（拒收）
  • 移除 mark（标记）
  • 新增 review（审核）
  • 新增 discard（丢弃）

3.2 执行动作集合对比

动作值变更前显示名称变更后显示名称变更类型
block → reject 阻断 拒收 改名 值和文案同时变更
quarantine 隔离 隔离 不变
mark 标记 — 移除
review — 审核 新增
discard — 丢弃 新增

3.3 变更范围（类型层 + Serde + UI + i18n）

文件变更内容
src/types/rbl-filter.ts RBLFilterProductAction 类型：'block' | 'quarantine' | 'mark' | 'greylist' → 'reject' | 'quarantine' | 'review' | 'discard' | 'greylist'；RBLProductActionLabels 映射同步更新
src/components/security/rbl-config-serde.ts RblImmediateAction：'block' | 'quarantine' | 'mark' → 'reject' | 'quarantine' | 'review' | 'discard'；parseRblConfig 增加旧数据兼容映射（block→reject，mark→reject）；DEFAULT_RBL_CONFIG.action 从 'block' 改为 'reject'
src/components/security/RBLFilterPage.tsx ACTION_TIP_KEY、RBL_IMMEDIATE_ACTIONS、actionLabel useMemo、DEFAULT_RBL_CONFIG.action 全部对齐新动作集合
messages/zh.json actionBlock→actionReject（"拒收"），移除 actionMark/actionMarkTip，新增 actionReview/actionReviewTip、actionDiscard/actionDiscardTip
messages/en.json 同上（英文）
messages/ru.json 同上（俄文）
messages/th.json 同上（泰文）
src/components/security/rbl-config-serde.test.ts 测试 fixture 中 'mark'→'reject'，'block'→'reject'；期望值同步更新

3.4 执行动作 i18n key 完整清单（zh）

key中文文案说明
rblFilter.actionReject拒收立即 5xx REJECT，替代原 actionBlock
rblFilter.actionRejectTip立即拒绝连接，返回5xx错误。适用于高风险场景，可能误拦合法邮件Select 选项内联说明
rblFilter.actionQuarantine隔离不变
rblFilter.actionQuarantineTip将邮件放入隔离队列，等待管理员审核。平衡安全与可用性不变
rblFilter.actionReview审核新增
rblFilter.actionReviewTip邮件进入人工审核队列，等待管理员决策。适用于需要人工判断的场景新增
rblFilter.actionDiscard丢弃新增
rblFilter.actionDiscardTip静默丢弃邮件，不通知发件方。适用于确认为垃圾邮件的高风险场景新增

3.5 旧数据兼容逻辑

后端存量配置可能包含 product_action: 'block' 或 product_action: 'mark'。parseRblConfig 中通过 legacyMap 将两者均映射为 'reject'，前端读取时自动升级，不影响用户体验。保存时写入新值 'reject'，与后端协商一致。
