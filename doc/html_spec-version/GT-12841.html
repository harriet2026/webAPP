智能体调查与处置卡片说明文案修正（消除异常字符，补全语义）

路由：检测引擎配置 Tab
组件：智能体调查与处置卡片说明文案
变更类型：文案修正 · 2026-08-11

1.1 方案概述

「智能体调查与处置」卡片位于检测引擎配置页第二张核心卡片，卡片说明用于告知用户运行模式、防护等级、置信度分级与超时策略之间的作用关系。此前该说明文案中存在编码异常字符（乱码片段），影响可读性与专业度。

问题现象：卡片说明文案在渲染时夹带非预期的 Unicode 替换字符，导致语句在「防护等级与置信度分级决定处置方式」附近出现断裂或不可读片段，用户无法准确理解运行模式、防护等级、置信度分级与超时策略四者的关系描述。
最终实现方案：将卡片说明文案统一改写为语义完整、无异常字符的表述：「运行模式决定是否执行处置，防护等级与置信度分级决定处置方式；超时策略对所有旁路检测生效。」该句以分号分隔两层逻辑——前半句说明「是否处置」由运行模式决定，后半句说明「如何处置」由防护等级与置信度分级共同决定，并补充超时策略的适用范围。不改变卡片的字段来源、i18n key 结构和其余卡片内容（运行模式徽章、超时自动投递状态、分级策略摘要）。

置信度分级处置表格新增风险等级徽章（可疑/低危/中危/高危）

路由：检测引擎配置 → 智能体调查与处置 → 编辑 → 运行模式配置抽屉（实时检测）
组件：置信度分级处置表格
变更类型：信息层级优化 · 2026-08-11

2.1 方案概述

「运行模式配置」抽屉选择「实时检测」时，下方展示「置信度分级处置」表格：按 0–100 连续区间分为 4 段，每段配置对应的处置动作。此前表格仅有「置信度区间」「处置动作」「标记设置」三列，用户需要自行换算每个数值区间对应的风险严重程度。

最终实现方案：在「置信度区间」与「处置动作」之间新增「风险等级」列，按置信度区间从低到高自动派生 4 个等级标签——0–40「可疑」、40–70「低危」（并列展示「低风险」提示）、70–90「中危」、90–100「高危」；四档采用中性灰、蓝色、橙色、红色的语义色阶，颜色强度随风险等级递增，帮助用户在配置处置动作前快速判断该区间的严重程度。风险等级为界面展示派生值，不作为独立可编辑字段，不改变置信度区间的数据结构、校验规则或保存逻辑。

置信度区间编辑器数字与列宽度优化（完整显示两位/三位数字）

路由：检测引擎配置 → 智能体调查与处置 → 编辑 → 运行模式配置抽屉（实时检测）
组件：confidence-bands-editor.tsx
变更类型：可用性优化 · 2026-08-11

3.1 方案概述

置信度分级处置表格中，「置信度区间」列由两个数字输入框（起始值、结束值）以短横线分隔组成。此前区间列宽度和数字输入框宽度偏窄，当区间边界为两位数（如 40、70、90）或三位数（100）时，数字在输入框内出现裁切或视觉拥挤，尤其在新增风险等级列（变更 2）后可用横向空间进一步减少。

问题根因：区间列最小宽度固定为 128px，数字输入框宽度固定为 56px 且可收缩；输入框未设置文本居中和等宽数字样式，两位数、三位数在窄输入框中容易贴边或被截断，起始值、结束值与中间分隔符之间的间距也不足，导致整列在视觉上拥挤。
最终实现方案：区间列最小宽度由 128px 调整为 160px；区间输入框宽度由 56px 调整为 64px，并设置为不收缩（flex-shrink: 0）；输入框增加水平内边距、文本居中对齐，并使用 tabular-nums 等宽数字样式，确保数字对齐美观；区间两端（起始值输入框、分隔符、结束值输入框）之间使用更宽的间距，避免相互挤压。仅调整显示空间与输入框样式，不修改置信度区间的数据结构、校验规则、接口调用和保存逻辑，不新增或删除字段，不改变处置动作选项；窄屏场景沿用表格既有的横向滚动能力。
