1

事后处置时间线：事件来源白名单过滤（根本原因修复）

analysis-section.tsx · DISPOSAL_SOURCES

1.1 问题根因

原过滤逻辑为黑名单，仅排除 event_source === 'postfix'，导致 antispam · policy_decided、antispam · quarantine_pending 等投递流程/策略裁决事件穿透过滤，出现在事后处置时间线中，且因这些值不在映射表中，渲染原始英文。

1.2 修复方案

改为白名单：仅保留 admin_api 和 threat_retro_agent 两种来源的事件。

// 修复前（黑名单）
const disposalEvents = useMemo(
  () => events.filter((ev) => ev.event_source !== 'postfix'),
  [events],
);

// 修复后（白名单）
const DISPOSAL_SOURCES = new Set(['admin_api', 'threat_retro_agent']);
const disposalEvents = useMemo(
  () => events.filter((ev) => DISPOSAL_SOURCES.has(ev.event_source ?? '')),
  [events],
);

1.3 白名单来源说明

event_source触发方说明
admin_api管理员手动管理员在详情页或列表页手动发起的召回操作
threat_retro_agent威胁回溯智能体威胁回溯智能体依据配置策略（recall / notify）自动发起的操作
业务边界：事后处置时间线只展示"事后处置动作"，不展示邮件投递流水（postfix）或策略裁决事件（antispam）。

2.2 操作类型枚举（完整）

2.3 实现方案

// analysis-section.tsx
const OPERATION_TYPE_KEY_MAP: Record<string, string> = {
  'admin_api:recall':          'adminApiRecall',
  'threat_retro_agent:recall': 'threatRetroAgentRecall',
  'threat_retro_agent:notify': 'threatRetroAgentNotify',
};

function getOperationTypeLabel(
  source: string | undefined,
  type: string | undefined,
  t: TFn,
): string {
  if (!type) return '—';
  const key = `${source ?? ''}:${type}`;
  const subKey = OPERATION_TYPE_KEY_MAP[key];
  if (!subKey) return type; // fallback 到原始值
  return t(`operationType.${subKey}`);
}

i18n 命名空间：emailDisposal.detail.analysis.operationType.{adminApiRecall | threatRetroAgentRecall | threatRetroAgentNotify}
