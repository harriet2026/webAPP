1. 需求背景与目标

附件安全检测长期将反病毒引擎、图片识别、加密附件识别等子引擎与结构性限制（附件数量、大小、嵌套层数等）合并归入同一个“附件安全检测”模块进行判定与展示，管理员难以从处置依据、检测流程等结果页面上分辨命中的是附件安全检测下的哪一类具体策略。本需求在附件安全检测能力体系下，新增“附件沙箱检测”子引擎，对接奇安信附件沙箱，将可疑附件送入沙箱环境动态执行分析，按行为风险等级或分析超时结果分别给出处置动作，并让沙箱命中结果在处置依据、检测流程、事后处置时间线等结果展示场景中具备独立、可追溯的归属标签。

目标项说明
沙箱规则模块新增“附件沙箱检测”规则模块，支持按方向、文件类型/自定义扩展名命中后送入沙箱动态分析。
风险处置低/中/高三档风险等级分别配置执行动作（隔离/审核/丢弃/不设置）与附件附加策略（标记/丢弃附件/不设置），标记附加策略下可组合选择标记生效位置。
超时处置支持沙箱分析超时或引擎不可用场景下的处置：召回、通知管理员、通知收件人，三者可任意组合勾选。
平台级配置新增平台级沙箱检测配置：最大分析文件大小、分析超时阈值，统一作用于云网关及多租户产品形态。
检测流程拆分阶段3的附件安全检测由单一合并判定拆分为“基础限制/反病毒引擎/附件沙箱/图片识别/加密附件”五个独立子项，父项状态由子项聚合，附件沙箱子项新增“超时”专属状态。
归属标签处置依据卡片与详情页为附件安全检测的各子引擎（含附件沙箱）补充“附件安全检测 › 子引擎名”两级归属标签，不改变现有按子引擎独立筛选的能力。
召回时间线沙箱超时且规则超时配置勾选“召回”时，在事后处置时间线中补充一条召回执行记录，区分成功与失败两种执行结果。

2. 数据模型

2.1 SandboxRule 规则模型

字段类型说明
directionDirection[]检测范围方向，支持接收 / 外发 / 域内任意组合多选。
sender_recipient_filter_enabledboolean特定收发信人筛选开关。
file_type_categoriesstring[]预置文件类型分类（office / script / exec）。
custom_extensionsstring[]自定义扩展名，需以 . 开头。
risk_actionsSandboxRiskActionConfig低 / 中 / 高三级风险各自独立的 SandboxRiskLevelConfig（执行动作 action + 附加策略 attachment_policy + 标记位置 mark_locations），执行动作与附加策略至少设置一项，不可同时为 none。
timeoutSandboxTimeoutConfig超时处置动作集合 actions（recall / notify_admin / notify_recipient 可任意组合）及启用通知管理员时的 admin_email。

规则列表按 created_at 升序排列，一个附件命中的第一条已启用规则生效，不叠加匹配多条。

2.2 PlatformSandboxPolicy 平台级配置模型

字段说明
max_file_size_mb最大分析文件大小（MB），超出不送入沙箱分析。
analysis_timeout_seconds分析超时阈值（秒），作用于云网关及多租户产品形态，不按租户单独配置。

2.3 邮件详情关联字段

字段类型说明
sandbox_timeoutboolean（可选）标记本次沙箱行为分析在时限内未产出结论，区别于“未命中规则”的通过态。
sandbox_recall_result'success' | 'failed'（可选）标记该邮件是否因沙箱超时触发召回及其执行结果。
CheckStatus 新增枚举值'timeout'检测流程阶段3附件沙箱子项在超时场景下的独立状态值。

5. 检测流程阶段3子引擎拆分

use-detection-stages.ts 将阶段3的“附件安全检测”由单一叶子判定项，改造为分组节点，下辖五个独立子项：

子引擎page key
基础限制attachment_basic_limit
反病毒引擎attachment_antivirus
附件沙箱检测attachment_sandbox
图片识别attachment_image_detect
加密附件attachment_encrypted

父项状态由五个子项按 threat > timeout > suspicious > pass > skipped 优先级聚合得出。附件沙箱子项新增专属判定函数，结合 MailLogDetail.sandbox_timeout 字段，在未命中高危行为规则但检测超时时返回独立的 timeout 状态，区别于笼统的“可疑”或“通过”。

analysis-section.tsx 检测项渲染扩展为支持嵌套：父项默认展开，子项在父项下方以浅底浅边框的子分组容器呈现，沿用项目既有“卡片嵌套”视觉惯例，不引入新的颜色或阴影层级。
