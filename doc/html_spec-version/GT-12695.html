1

黑名单执行动作「阻断」→「拒收」

文案变更 · 黑名单规则

黑名单规则的执行动作 reject 原显示为「阻断」，更改为「拒收」，语义更准确（向发信方返回 SMTP 拒绝响应，邮件不进入系统）。

1.1 逐元素说明

元素变更前变更后覆盖语言
执行动作下拉选项 reject 标签 阻断 / Block 拒收 / Reject zh / en / ru / th
规则列表 Badge 文字（action 列） 阻断 / Block 拒收 / Reject 同上
配置示例卡片标题 阻断垃圾邮件发送者 拒收垃圾邮件发送者 zh / en / ru / th

1.2 影响文件

文件改动摘要
messages/zh.jsonsenderFilter.action_reject：「阻断」→「拒收」；exampleBlockSpam 标题同步更新
messages/en.jsonaction_reject：「Block」→「Reject」；exampleBlockSpam 同步
messages/ru.jsonaction_reject：「Блокировать」→「Отклонить」
messages/th.jsonaction_reject：「บล็อก」→「ปฏิเสธ」
2

黑名单新增「丢弃」执行动作

功能新增 · 黑名单规则

黑名单执行动作新增 discard（丢弃）选项：静默丢弃邮件，发信方收到投递成功响应但邮件实际被丢弃（蜜罐场景）。在下拉中排在「拒收」之后，规则列表 Badge 使用 error 样式（与「拒收」一致）。

2.1 逐元素说明

元素说明
下拉选项「丢弃」新增于「拒收」之后，value=discard
选项说明文字「静默丢弃邮件，发信方收到投递成功响应但邮件实际被丢弃」
规则列表 Badge 样式error 变体（红色），与「拒收」保持一致

2.2 影响文件

文件改动摘要
src/types/sender-filter.tsBlacklistAction 联合类型新增 'discard'
src/components/security/sender-filter/SenderFilterDrawer.tsxZod schema、actionLabel 映射、下拉 JSX 新增 discard
src/components/security/sender-filter/SenderFilterTable.tsxactionVariant 新增 discard → 'error'
messages/zh.json 等 4 个语言文件新增 action_discard 及 action_discard_desc
3

执行动作下拉新增说明文字

UX 优化 · 黑名单 / 白名单规则

配置执行动作时，下拉每个选项增加一行灰色说明文字，帮助用户理解各动作语义。同时将 SelectContent 宽度固定为 w-72（288 px），避免说明文字被截断；说明文字加 whitespace-normal 可自动换行。

3.1 逐元素说明

动作说明文字（zh）
拒收向发信方返回 SMTP 拒绝响应，邮件不进入系统
丢弃静默丢弃邮件，发信方收到投递成功响应但邮件实际被丢弃
隔离邮件进入隔离区，管理员可审阅后决定是否放行
审核邮件正常投递，同时写入审核日志供管理员事后审查
投递允许邮件通过，跳过后续检测直接投递至收件箱

3.2 影响文件

文件改动摘要
SenderFilterDrawer.tsxSelectContent 加 className="w-72"；各 SelectItem 内含说明 span + whitespace-normal leading-snug
messages/{zh,en,ru,th}.json新增全部 5 个 action_*_desc key
4

修复白名单配置示例展示黑名单内容并跳转黑名单的 Bug

Bug 修复 · 白名单规则

4.1 根因分析

「查看配置示例」展开后，两个示例卡片的「使用该示例」回调中硬编码了 form.setValue('list_type', 'blacklist', ...)，无论当前处于白名单 Tab，均会将表单强制切换为黑名单，导致后续逻辑跳转至黑名单页面。

4.2 逐元素说明

变更点变更前变更后
配置示例区块渲染逻辑 始终展示两个黑名单示例卡片 按 watchListType 分支：黑名单 Tab 展示黑名单示例，白名单 Tab 展示白名单示例
黑名单示例 1 「阻断垃圾邮件发送者」· list_type: 'blacklist' 「拒收垃圾邮件发送者」· 移除 list_type 赋值
黑名单示例 2 「隔离可疑来源」· list_type: 'blacklist' 「隔离可疑来源」· 移除 list_type 赋值
白名单示例 1（新增） — 「放行可信发信人」· sender_config.type: 'individual'，action: 'accept'
白名单示例 2（新增） — 「放行可信域名」· sender_config.type: 'domain'，action: 'accept'

4.3 影响文件

文件改动摘要
SenderFilterDrawer.tsx配置示例 CollapsibleContent 改为 watchListType === 'blacklist' ? ... : ... 分支渲染；移除所有 form.setValue('list_type', 'blacklist') 调用
messages/{zh,en,ru,th}.json新增 exampleAllowTrustedSender、exampleAllowTrustedSenderDesc、exampleAllowTrustedDomain、exampleAllowTrustedDomainDesc
5

白名单「放行」→「投递」· 移除白名单模式 UI 字段

文案变更 / UI 移除 · 白名单规则

白名单执行动作 accept 的显示文案由「放行」改为「投递」，语义更贴合实际行为（直接投递至收件箱）。同时将新建/编辑抽屉中「白名单模式」下拉字段从 UI 层移除（类型定义与 API 层保留，不影响已有数据）。

5.1 逐元素说明

元素变更前变更后
执行动作下拉 accept 标签 放行 / Allow 投递 / Deliver
「白名单模式」字段（执行动作下方） 显示（跳过内容检测 / 直接投递） 移除（不渲染）
表单 whitelist_mode 默认值 'bypass_content' undefined
superRefine 白名单必填校验 白名单下 whitelist_mode 为必填，否则报错 移除该校验
注意：whitelist_mode 字段仍保留在 src/types/sender-filter.ts 和 src/lib/api/sender-filter.ts 中，数据层向后兼容，仅 UI 层不再展示。

5.2 影响文件

文件改动摘要
messages/{zh,en,ru,th}.jsonaction_accept：「放行」→「投递」；action_accept_desc 同步更新
SenderFilterDrawer.tsx移除「白名单模式」Select 字段 34 行；移除 watchWhitelistMode 声明；移除 getDefaultPriority 函数；移除 WhitelistMode import；superRefine 移除白名单必填校验；resetForm whitelist_mode 默认值改为 undefined；handleSubmit 始终以 undefined 透传
