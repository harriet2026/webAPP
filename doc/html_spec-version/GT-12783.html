GT-12778 运营TOP与趋势-榜单序号错位且内网地理位置标签重复问题解决

路由: /statistics/ops-top-trend
组件: src/components/statistics/ops-top-trend/TopTable.tsx
2026-08-05

1.1 问题描述

在"运营TOP与趋势"页面的连接会话TOP榜单中，存在两个视觉异常问题：

  1. 序号列错位：飙升行（isSpike=true）序号列额外渲染了火焰图标（Flame，12px），通过 gap-1 将排名徽标向右推移约 16px；普通行无图标，徽标从最左侧开始。导致火焰行的排名徽标与普通行视觉上不对齐。
  2. 内网标签重复：当 row.metrics.isInternal=true 时，来源IP列已显示"内网"标签；与此同时 geoLocation 字段值为 'internal'，地理位置列也独立渲染了一个"内网"标签，同一行出现两个相同含义的"内网"徽章。

问题截图 S-1 — 连接会话 TOP 榜单，序号错位 + 内网标签重复（修复前）

路径：统计报表 → 运营TOP与趋势 → 连接会话 → 近7日 → TOP 10

国际化合规说明：修复代码不涉及新增 i18n key，仅使用现有的 t('internal') 与结构性 JSX 调整，无需修改任何语言文件。 地理位置列内网行改为渲染 <span>-</span> 纯文本占位， 语义上表示"内网地址无地理位置信息"，无需国际化。

1.2 变更 1：榜单序号列火焰图标占位修复（序号错位）

1.2.1 方案概述

在序号列 <td> 内，为火焰图标外层新增一个固定宽度 w-3 shrink-0 的 <span> 占位容器。无论当前行 isSpike 是否为真，该占位容器始终渲染且宽度固定，确保排名徽标始终从相同的 x 轴位置开始，消除视觉错位。

  <span className={`inline-flex h-5 w-5 ... ${RANK_BADGE[row.rank] ?? '...'}`}>
    {row.rank}
  </span>
</div>
<div className="flex items-center gap-1">
  {/* 固定宽度占位槽，保证排名徽标始终左对齐 */}

    {row.isSpike ? (<Flame className="h-3 w-3 text-orange-500" />) : null}
  </span>
  <span className={`inline-flex h-5 w-5 ... ${RANK_BADGE[row.rank] ?? '...'}`}>
    {row.rank}
  </span>
</div>

1.3 变更 2：地理位置列内网标签去重（重复标签）

1.3.1 方案概述

在 geoLocation 列渲染逻辑中，新增判断：当 isInternalGeo 为 true 且 row.metrics.isInternal 同样为 true 时（即来源IP列已展示"内网"标签），直接返回 <span className="text-muted-foreground">-</span> 占位， 不再渲染重复的"内网" Badge。内网地址本身无地理位置含义，以 - 占位语义更清晰。

}

GT-12468 运营TOP与趋势-连接异常失败与策略拒绝未分开统计问题解决

路由: /statistics/ops-top-trend
文件: messages/zh.json / en.json / ru.json / th.json
2026-08-05

2.1 问题描述

连接会话维度的"失败次数"列（failureCount）及相关 tooltip，将两种性质完全不同的失败 合并为同一个数字展示，导致语义歧义：

失败类型 定义 口径来源
连接传输异常 建连后立即断开、SMTP 握手失败、TLS 握手失败等 Postfix SMTP session log（已到达服务器）
策略主动拒绝 黑白名单、反垃圾规则、并发限制等 Postfix policy/restriction 层（主动拦截，非"异常"）

当前 zh.json 中 leftColTip.failureCount 仅为极简的"失败次数"，无任何口径说明， 用户无法判断失败率 100% 究竟是"遭受网络扫探攻击"还是"被策略正常拦截"。

方案 A（本次落地）：Tooltip 口径说明增强——仅修改四个语言文件中的 3 个 key 文案， 在 tooltip 中明确说明"失败包含：传输异常；不含：策略拒绝（黑白名单/反垃圾规则/并发限制）"， 零前端逻辑变更，零 API 变更。 方案 B（拆列，需后端新字段）留待后续迭代。
可见度说明：连接会话维度在云网关 / AI 版多租户 / 传统版多租户产品形态下 仅平台管理员可见，租户管理员不可见。scope.ts 的 computeIsPlatformScope() 与 DimensionTabs.tsx 的 tab 过滤逻辑 已合规，本次不修改。

D — 差异与待确认

D-001 — 占位容器宽度与火焰图标尺寸一致性
