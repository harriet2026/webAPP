# GT-14394 规则效能统计页面，支持基于策略流水线范式筛选

## 1. 需求背景

规则效能统计页面用于查看支持观察模式的策略命中情况、预期处置结果和规则效能明细。原有筛选模块按照独立模块平铺展示，阶段、策略模块和统计结果之间缺少明确的策略流水线关系，用户难以按照策略执行顺序定位数据。

本需求按照策略流水线范式优化规则效能统计筛选模块，使阶段筛选、策略模块筛选、KPI 卡片、观察超期提醒和效能明细数据使用同一套筛选条件。同时，页面只展示已经支持观察模式并接入规则效能统计的策略模块，不展示不具备观察统计能力的策略模块。

本需求只调整规则效能统计页面及其筛选数据映射，不修改其他安全策略模块、策略流水线配置和邮件处置中心既有功能。

## 2. 需求目标

- 按策略流水线顺序展示规则效能统计阶段。
- 只展示支持观察模式的策略模块。
- 阶段筛选与策略模块筛选保持联动。
- 选择阶段后，策略模块、KPI 卡片、超期提醒和效能明细同步变化。
- 租户管理员视角不展示阶段1及其策略。
- 保持时间范围、观察时长和重置筛选的既有能力。
- 不引入异常符号“？”。

## 3. 功能范围

### 3.1 覆盖内容

| 功能 | 说明 |
| --- | --- |
| 时间范围筛选 | 支持预设时间范围和自定义日期范围 |
| 阶段筛选 | 按策略流水线阶段顺序展示，带阶段颜色和模块数量 |
| 策略模块筛选 | 按阶段分组展示，仅展示支持观察模式的模块 |
| 观察时长筛选 | 支持全部、不同观察时长范围等既有条件 |
| 统计结果联动 | KPI、观察超期提醒、效能明细和分页同步更新 |
| 权限视角 | 租户管理员不展示阶段1策略 |
| 重置 | 恢复当前视角下的默认筛选条件并回到第一页 |

### 3.2 不在本需求范围内

- 不修改策略流水线页面的阶段配置和策略执行逻辑。
- 不新增其他策略模块的观察模式能力。
- 不修改观察模式的保存、启用、停用和正式处置逻辑。
- 不修改邮件处置中心的筛选、分页和处置操作。
- 不新增与规则效能统计无关的后端接口。
- 不改变已有 KPI 指标的业务含义。

## 4. 支持观察模式的阶段与模块

规则效能统计页面展示范围为：

```text
策略流水线阶段模块
∩
已支持观察模式且已接入效能统计的模块
∩
当前用户视角允许查看的模块
```

### 4.1 阶段顺序

页面按照以下顺序展示阶段：

1. 阶段2：收发信人策略
2. 阶段3：内容层
3. 阶段4：智能分析层
4. 阶段5：综合策略

阶段1属于 IP 策略。租户管理员视角下不可见阶段1及其策略。当前规则效能统计只展示已经支持观察模式并纳入统计的阶段，因此没有观察统计能力的阶段不出现在阶段筛选中。

### 4.2 阶段与模块归属

| 阶段 | 阶段名称 | 支持观察模式的策略模块 |
| --- | --- | --- |
| 阶段2 | 收发信人策略 | 身份认证与仿冒检测、发信人策略、收件人检测、发信行为管控 |
| 阶段3 | 内容层 | 内容规则、附件安全检测、意图引擎 |
| 阶段4 | 智能分析层 | 钓鱼邮件智能体 |
| 阶段5 | 综合策略 | 相似邮件检测、相同主题检测、高级过滤规则 |

阶段和模块的归属、名称及顺序必须与策略流水线保持一致。策略模块是否出现在本页面，还需要满足已经实现观察模式并能够提供规则效能统计数据的条件。

## 5. 筛选模块设计

### 5.1 整体布局

筛选卡片使用统一的横向筛选结构：

```text
漏斗图标  时间范围  自定义日期范围  阶段  策略模块  观察时长  重置
```

桌面端保持横向排列，窄屏允许换行。筛选卡片使用白色背景、浅色边框、圆角和轻微阴影，所有筛选控件保持统一高度和垂直对齐。

### 5.2 时间范围

时间范围使用下拉筛选框，不使用分段按钮。

支持选项：

- 今天
- 近7天
- 近30天
- 自定义

选择“自定义”后，在时间范围筛选框右侧显示日期范围选择组件，不得将日期选择组件移动到阶段筛选之后。

日期范围组件要求：

- 使用日期范围选择器；
- 支持开始日期和结束日期；
- 支持双月查看；
- 选择完成后在按钮中显示日期范围；
- 日期范围校验失败时在组件内展示错误提示；
- 时间范围变化后重置效能明细分页为第一页。

### 5.3 阶段筛选

阶段筛选使用单选下拉框。

默认状态显示“全部阶段”，在当前用户视角下代表所有可见且支持观察模式的阶段。

每个阶段选项展示：

- 阶段颜色圆点；
- 阶段名称；
- 支持观察模式的模块数量；
- 当前选中项显示蓝色高亮和勾选图标。

租户管理员视角下：

- 不展示阶段1；
- 不展示阶段1下的策略模块；
- “全部阶段”不包含阶段1；
- 不允许通过前端残留状态或查询参数请求阶段1数据。

### 5.4 策略模块筛选

策略模块筛选使用分组下拉框。

选择“全部阶段”时，模块下拉按阶段分组展示所有当前视角可见且支持观察模式的模块。

选择具体阶段后：

- 仅展示当前阶段的策略模块；
- 自动将模块筛选范围切换为当前阶段模块全集；
- 清理上一阶段遗留的模块选择；
- 模块下拉不展示其他阶段模块；
- 分组标题展示阶段颜色圆点和阶段名称；
- 模块数量较多时，下拉内容在限定高度内滚动。

策略模块手动选择或取消时，不自动反向修改阶段筛选。阶段筛选和模块筛选的最终组合必须始终限制在当前阶段和当前视角允许的模块集合内。

### 5.5 观察时长

观察时长继续使用统一下拉筛选框，保持既有选项和查询含义。

该筛选只改变观察时长条件，不改变策略模块的阶段归属和可见性。

### 5.6 重置

点击“重置”后：

- 时间范围恢复默认值；
- 自定义日期范围清空；
- 阶段恢复为“全部阶段”；
- 策略模块恢复为当前视角下的全部支持观察模式模块；
- 观察时长恢复默认值；
- 效能明细分页回到第一页；
- 仅触发一次统计数据刷新。

## 6. 阶段联动与数据查询

### 6.1 筛选状态

页面维护以下筛选状态：

```ts
type StageId = 'stage2' | 'stage3' | 'stage4' | 'stage5';

type RuleEffectivenessFilters = {
  timeRange: TimeRange;
  customRange?: CustomRange;
  stage: StageId | 'all';
  modules: ModuleFilterOption[];
  observeDuration: ObserveDurationBucket | 'all';
  page: number;
};
```

阶段列表、模块列表和权限过滤结果使用同一份配置源，避免阶段下拉与模块下拉出现不一致。

### 6.2 阶段切换

用户选择具体阶段时：

1. 页面读取当前视角下的可见阶段列表。
2. 根据阶段 ID 查找支持观察模式的模块列表。
3. 将模块筛选设置为该阶段模块全集。
4. 清理不属于当前阶段的旧模块选择。
5. 分页回到第一页。
6. 重新生成统计查询参数。
7. 请求并展示新的 KPI、超期提醒和效能明细。

用户选择“全部阶段”时：

1. 页面读取当前视角下全部可见阶段。
2. 合并各阶段支持观察模式的模块列表。
3. 模块筛选恢复为全部可见观察模块。
4. 分页回到第一页。
5. 重新请求统计数据。

### 6.3 查询参数

阶段筛选最终转换为模块查询参数，不单独依赖仅存在于前端的阶段字段：

```text
阶段选择
→ 支持观察模式的模块集合
→ modules / similarDetectionTypes
→ 统计查询参数
→ KPI、提醒和明细统一使用查询结果
```

查询参数必须经过以下过滤：

- 当前阶段允许的模块；
- 当前用户视角允许的模块；
- 支持观察模式的模块；
- 当前模块筛选选择。

不得将阶段1或不支持观察模式的模块传入统计查询。

## 7. 统计结果联动

阶段筛选和模块筛选变化后，以下内容必须同步更新：

### 7.1 KPI 卡片

KPI 卡片只统计当前筛选条件下的观察数据，包括：

- 策略命中总量；
- 有效拦截率；
- 观察模式命中量；
- 活跃规则数；
- 其他现有统计指标。

选择阶段2时，KPI 不能继续包含阶段3、阶段4或阶段5的数据。

### 7.2 观察超期提醒

观察超期提醒使用与 KPI 相同的阶段、模块、时间范围和观察时长条件，不单独读取未过滤的数据。

### 7.3 效能明细

效能明细只展示当前筛选条件下的规则数据：

- 规则所属模块符合当前阶段；
- 规则属于当前用户允许的范围；
- 规则支持观察模式；
- 分页、总数和排序基于新的筛选结果重新计算。

### 7.4 分页

以下条件变化时，明细分页必须回到第一页：

- 时间范围变化；
- 自定义日期变化；
- 阶段变化；
- 策略模块变化；
- 观察时长变化；
- 租户或视角变化。

## 8. 权限与视角规则

### 8.1 系统管理员

系统管理员可以查看当前已接入观察统计的阶段2、阶段3、阶段4和阶段5模块。

如果未来阶段1下的策略接入观察模式和规则效能统计，系统管理员可以按策略流水线配置展示阶段1；租户管理员仍必须隐藏阶段1。

### 8.2 租户管理员

租户管理员只查看租户范围内可见的策略模块，且：

- 阶段1不可见；
- 阶段1模块不可出现在模块下拉；
- 阶段1数据不可出现在 KPI、提醒和明细中；
- 不得通过 URL、缓存状态或前端残留筛选条件恢复阶段1；
- 当前阶段变为不可见时，自动恢复为“全部阶段”并清理模块筛选。

## 9. 验收标准

### 9.1 筛选展示

- 时间范围为统一下拉筛选框。
- 选择自定义后，日期范围组件紧邻时间范围筛选框。
- 阶段下拉展示颜色、阶段名称和观察模块数量。
- 策略模块下拉按阶段分组。
- 模块分组和阶段顺序与策略流水线一致。
- 不支持观察模式的策略模块不展示。

### 9.2 阶段联动

- 选择阶段2后，只出现阶段2支持观察模式的模块。
- 选择阶段3后，只出现内容规则、附件安全检测和意图引擎。
- 选择阶段4后，只出现钓鱼邮件智能体。
- 选择阶段5后，只出现相似邮件检测、相同主题检测和高级过滤规则。
- 选择“全部阶段”后恢复当前视角下全部支持观察模式模块。

### 9.3 统计联动

- 阶段变化后 KPI 卡片数据发生对应变化。
- 阶段变化后观察超期提醒数据发生对应变化。
- 阶段变化后效能明细只展示对应阶段数据。
- 阶段变化后总数和分页正确重算。
- 模块变化后 KPI、提醒和明细同步变化。

### 9.4 权限验证

- 租户管理员看不到阶段1。
- 租户管理员看不到阶段1模块。
- 租户管理员的“全部阶段”查询不包含阶段1数据。
- 租户管理员无法通过残留状态请求阶段1统计数据。

### 9.5 兼容性

- 不影响其他策略配置页面。
- 不影响邮件处置中心既有功能。
- 不改变观察模式配置和保存逻辑。
- 页面文案不出现异常符号“？”。
- 时间、阶段、模块、观察时长和重置操作均可正常使用。

实现完成后至少验证：

1. 规则效能统计页面桌面端筛选布局。
2. 自定义日期范围选择和时间筛选联动。
3. 阶段下拉的顺序、颜色和模块数量。
4. 阶段切换后的模块分组变化。
5. 阶段切换后的 KPI、提醒、明细和分页变化。
6. 系统管理员和租户管理员视角下阶段1可见性。
7. 支持观察模式模块的完整性和顺序。
8. ESLint、类型检查或项目既有定向校验。
9. 页面文案中不存在异常符号“？”。

## 12. 变更说明

本需求文档记录规则效能统计筛选模块的优化实现方案：以策略流水线为展示顺序，以观察模式支持能力为模块过滤条件，以用户视角为权限过滤条件，并将筛选条件统一作用于统计页面全部数据区域。其他功能模块保持原有行为不变。
