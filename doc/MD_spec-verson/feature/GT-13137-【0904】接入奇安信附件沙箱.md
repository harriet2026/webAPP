# GT-13137 【0904】接入奇安信附件沙箱

## 1. 需求背景

附件安全检测长期将反病毒引擎、图片识别、加密附件识别等子引擎与结构性限制（附件数量、大小、嵌套层数等）合并归入同一个"附件安全检测"模块进行判定与展示，管理员难以从处置依据、检测流程等结果页面上分辨命中的是附件安全检测下的哪一类具体策略。本需求在附件安全检测能力体系下，新增"附件沙箱检测"子引擎，对接奇安信附件沙箱，将可疑附件送入沙箱环境动态执行分析，按行为风险等级或分析超时结果分别给出处置动作，并让沙箱命中结果在处置依据、检测流程、事后处置时间线等结果展示场景中具备独立、可追溯的归属标签。

## 2. 需求目标

- 新增"附件沙箱检测"规则模块，支持按方向、文件类型/自定义扩展名命中后送入沙箱动态分析。
- 支持低危、中危、高危三档风险等级分别配置执行动作（隔离/审核/丢弃）与附件附加策略（标记/丢弃附件/不设置），标记附加策略下可组合选择标记生效位置。
- 支持沙箱分析超时或引擎不可用场景下的处置：召回、通知管理员、通知收件人，三者可任意组合勾选。
- 新增平台级沙箱检测配置：最大分析文件大小、分析超时阈值，统一作用于云网关及多租户产品形态。
- 在检测流程"阶段3"中将附件安全检测由单一合并判定拆分为"基础限制/反病毒引擎/附件沙箱/图片识别/加密附件"五个独立子项，父项状态由子项聚合，附件沙箱子项新增"超时"专属状态。
- 在处置依据卡片与详情页中为附件安全检测的各子引擎（含附件沙箱）补充"附件安全检测 › 子引擎名"两级归属标签，同时不改变现有按子引擎独立筛选的能力。
- 沙箱超时且规则超时配置勾选"召回"时，在事后处置时间线中补充一条召回执行记录，区分成功与失败两种执行结果。
- 全部新增文案复用项目现有国际化框架（`next-intl`），覆盖中/英/泰/俄四语言。

## 3. 最终实现方案

### 3.1 数据模型

新增 `SandboxRule` 规则模型（`src/types/attachment-security.ts`），核心字段：

- `direction: Direction[]`：检测范围方向，支持接收/外发/域内任意组合多选。
- `file_type_categories: string[]`：预置文件类型分类（`office`/`script`/`exec`）。
- `custom_extensions: string[]`：自定义扩展名，需以 `.` 开头。
- `risk_actions: SandboxRiskActionConfig`：低/中/高三级风险各自独立的 `SandboxRiskLevelConfig`（执行动作 `action` + 附加策略 `attachment_policy` + 标记位置 `mark_locations`），执行动作与附加策略至少设置一项，不可同时为 `none`。
- `timeout: SandboxTimeoutConfig`：超时处置动作集合 `actions`（`recall`/`notify_admin`/`notify_recipient` 可任意组合）及启用通知管理员时的 `admin_email`。

新增平台级配置模型 `PlatformSandboxPolicy`：`max_file_size_mb`、`analysis_timeout_seconds`，作用于云网关及多租户产品形态的沙箱分析边界。

规则列表按 `created_at` 升序排列，一个附件命中的第一条已启用规则生效，不叠加匹配多条。

### 3.2 附件安全检测页面新增"沙箱检测"页签

- `AttachmentSecurityPage.tsx` 新增"沙箱检测"页签，入口路由支持 `?stage3=attachment&stage3Tab=sandboxRules` 直达。
- 新建/编辑规则通过 `SandboxRuleDrawer.tsx` 抽屉完成，分为四个分区：检测范围（多选分段控件）、文件类型（分类勾选器 + 自定义扩展名输入）、风险等级处置（低/中/高三档独立配置执行动作与附加策略，附加策略为"标记"时展开标记位置勾选）、超时处置（动作组合勾选 + 管理员邮箱条件校验）。
- 规则列表支持启停 Switch、编辑、删除、按名称搜索，接口对接 `mockSandboxRulesList`/`mockCreateSandboxRule`/`mockUpdateSandboxRule`/`mockSetSandboxRuleStatus`/`mockDeleteSandboxRule`。
- 表单校验：规则名称必填；检测范围至少一项；文件类型分类与自定义扩展名至少一项；超时动作至少一项；启用通知管理员时邮箱必填且格式校验；任一风险等级的执行动作与附加策略不可同时为"不设置"。

### 3.3 平台安全策略新增沙箱平台配置

`SandboxPlatformPanel.tsx` 在平台安全策略页面新增"沙箱检测"配置区，提供最大分析文件大小（MB）、分析超时时长（秒）两项输入，统一作用于云网关及多租户产品形态，不按租户单独配置。

### 3.4 检测流程"阶段3"子引擎拆分

`use-detection-stages.ts` 将阶段3的"附件安全检测"由单一叶子判定项，改造为分组节点，下辖五个独立子项（对应五个 page key）：

| 子引擎 | page key |
| --- | --- |
| 基础限制 | `attachment_basic_limit` |
| 反病毒引擎 | `attachment_antivirus` |
| 附件沙箱检测 | `attachment_sandbox` |
| 图片识别 | `attachment_image_detect` |
| 加密附件 | `attachment_encrypted` |

父项状态由五个子项按 `threat > timeout > suspicious > pass > skipped` 优先级聚合得出。附件沙箱子项新增专属判定函数，结合 `MailLogDetail.sandbox_timeout` 字段，在未命中高危行为规则但检测超时时返回独立的 `timeout` 状态（`CheckStatus` 新增枚举值），区别于笼统的"可疑"或"通过"。

`analysis-section.tsx` 检测项渲染扩展为支持嵌套：父项默认展开，子项在父项下方以浅底浅边框的子分组容器呈现，沿用项目既有"卡片嵌套"视觉惯例，不引入新的颜色或阴影层级。

### 3.5 处置依据"父级 › 子引擎"归属标签

`disposal-basis-config.ts` 为附件安全检测各子引擎（反病毒、附件沙箱、图片识别、加密附件及基础限制）补充 `moduleGroupZh/En/Th/Ru` 父级分组字段，统一取值"附件安全检测"，与各自独立的 `moduleZh`（如"附件沙箱检测"）分离存储。处置依据卡片与详情页据此渲染"附件安全检测 › 附件沙箱检测"两级面包屑展示，按子引擎独立筛选的既有能力保持不变。

新增 `ATT-SANDBOX` 处置依据条目，覆盖两类命中场景的多语言文案：

- 沙箱分析超时（按规则配置隔离），安全性未知。
- 沙箱动态分析检出高危行为，附带行为描述与风险等级。

新增 `POLICY_ROUTE_OVERRIDE` 映射，使 `ATT-SANDBOX` 处置依据的"查看规则"入口直达附件安全检测抽屉的"沙箱检测"页签（`/security/pipeline?stage3=attachment&stage3Tab=sandboxRules`）。

### 3.6 超时召回 → 事后处置时间线

`MailLogDetail` 新增可选字段 `sandbox_recall_result?: 'success' | 'failed'`，标记该邮件是否因沙箱超时触发召回及其执行结果。当邮件满足"`sandbox_timeout === true` 且命中沙箱规则超时配置勾选了 `recall`"时，事后处置时间线追加一条 `event_source: 'workflow.sandbox_recall'`、`event_type` 为"附件沙箱超时召回"的事件记录，与现有 `workflow.quarantine`/`workflow.sideline`/`workflow.audit`/`workflow.bounce` 同一命名体系，天然落入现有"非 postfix 来源即归入处置动作时间线"的过滤与渲染逻辑，未改动时间线渲染代码。

事件的 `event_type` 直接写中文文案，不接入 i18n 翻译层，与现有时间线事件的展示风格一致。

## 6. 变更范围

本需求覆盖附件沙箱检测规则模型、沙箱规则配置页面与抽屉、平台级沙箱配置、检测流程阶段3的附件安全检测子引擎拆分、处置依据归属标签、超时召回事后处置时间线记录，以及上述范围涉及的国际化文案。不改变反病毒引擎、图片识别、加密附件、基础限制四个既有子模块自身的判定与配置逻辑，不改变阶段1/2/4/5的既有结构，不改变事后处置时间线的渲染逻辑本身。
