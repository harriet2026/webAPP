# GT-14367 发信行为管控支持观察模式

## 1. 需求背景

发信行为管控模块的规则一旦启用即会立即对超过阈值的行为执行审核、隔离、丢弃或拒收等动作。用户在新建规则或调整已有规则的对象范围、维度阈值时，缺少一种"先观察命中情况、再正式生效"的过渡手段，容易因阈值设置不合理而误伤正常发信行为或漏拦异常发信行为。

本需求在发信行为管控模块新增"观察模式"能力：规则开启观察模式后仅记录命中日志，不实际执行规则动作，帮助用户在正式启用前验证规则的影响范围。

本次为纯前端交付，使用 mock 数据模拟观察模式的开启/关闭状态，暂不涉及后端接口改造。

## 2. 需求目标

- 在"新建/编辑"抽屉的基础设置区域，增加观察模式的启用/禁用开关。
- 在规则列表增加"观察模式"表头字段，并支持直接在列表中启用/禁用。
- 观察模式状态与规则的启用/禁用状态（`is_active`）互相独立，两者可分别控制。
- 复用项目现有国际化框架和 `Switch` 组件形态，不引入新的交互范式。
- 不修改发信行为管控之外的其他功能模块。

## 3. 最终实现方案

### 3.1 数据模型

- `BehaviorControlFormData` 增加可选字段 `observe_mode?: boolean`，供抽屉表单读写。
- 由于后端暂无承载该状态的字段，`observe_mode` 的值由 `BehaviorControlPage` 维护的本地 mock 态（`observeModes: Record<number, boolean>`，以规则 `id` 为键）注入到每一行，不进入规则的真实 CRUD 请求体，不随规则的创建、编辑、删除请求持久化到后端。

### 3.2 新建/编辑抽屉——基础设置（操作级说明）

- **打开抽屉**：用户在规则列表点击"新建规则"或某一行的"编辑"操作，抽屉展开，基础设置区域渲染在最上方。
- **字段位置与结构**：在基础设置区域、启用状态（`is_active`）字段的下方新增一行"观察模式"字段，结构为：字段标签 + 右侧 `Switch` 组件 + Switch 右侧的状态文案（复用现有的"启用"/"禁用"文案键）。
- **默认值填充（新建场景）**：
  1. 用户点击"新建规则"。
  2. 表单以空白态初始化，`observe_mode` 字段默认值为 `false`（关闭）。
  3. 观察模式 Switch 渲染为"关闭"态，右侧状态文案显示"禁用"。
- **回填（编辑场景）**：
  1. 用户点击某一行的"编辑"。
  2. `BehaviorControlPage` 从本地 `observeModes` 状态中按 `editing.rule.id` 取出当前观察模式值（未记录过则默认 `false`），通过 `observeMode` 属性传给抽屉。
  3. 观察模式 Switch 按该值渲染为开启或关闭态，右侧状态文案同步显示"启用"或"禁用"。
- **交互——切换开关**：
  1. 用户点击观察模式 Switch。
  2. Switch 视觉状态立即切换（开启 ↔ 关闭），右侧状态文案同步切换为"启用"/"禁用"。
  3. 表单内部字段 `observe_mode` 的值随之更新，但不触发提交，也不影响表单内其他字段（对象范围、维度阈值、方向、动作类型、启用状态等）的值。
- **交互——保存**：
  1. 用户点击抽屉底部的"保存"按钮。
  2. 表单当前的 `observe_mode` 值通过 `onObserveModeChange(savedId, observeMode)` 回调同步回 `BehaviorControlPage` 的本地 `observeModes` 状态（本次为纯前端 mock，不发起真实网络请求持久化该字段）。
  3. 抽屉关闭，规则列表对应行（新建则新增一行）按最新的 `observe_mode` 值重新渲染观察模式列。

### 3.3 规则列表——观察模式列（操作级说明）

- **列位置**：在规则列表表头新增"观察模式"列（`data-testid="behavior-control-col-observe-mode"`）。
- **单元格渲染**：
  1. 页面渲染规则列表时，每一行按 `observeModes[v.rule.id] ?? false` 的值渲染观察模式列的 `Switch` 组件：`true` 渲染为开启态，`false` 渲染为关闭态。
  2. Switch 的 `aria-label` 使用国际化的"观察模式"文案，保证屏幕阅读器可读。
- **交互——列表内直接切换**：
  1. 用户点击某一行观察模式列的 Switch。
  2. Switch 视觉状态立即切换（开启 ↔ 关闭）。
  3. 该操作仅更新对应规则行本地 mock 状态中的 `observe_mode` 字段，同一行的其余字段（对象范围、维度阈值、方向、动作类型、`is_active`、命中统计等）保持不变，不重新拉取整张列表。
  4. 操作不需要二次确认，不弹出额外的保存/取消对话框（即时生效于本地 mock 状态）。
- **与其他列的独立性**：切换"观察模式"列不影响"启用状态"列（`is_active`）的显示与取值，两者在同一行内并存、互不联动；反之，切换"启用状态"也不会重置该行的观察模式取值。

### 3.4 国际化

- 在 `behaviorControl` 命名空间下已有的 `form.observeMode`、`col.observeMode` 键基础上，复用 `filter.enabled`/`filter.disabled` 表达开关状态文案，未引入重复的语义键。
- 中文资源使用 UTF-8 编码，不引入 Unicode replacement character 或异常全角问号字符。
- 英文、俄文、泰文资源文件已同步补齐对应翻译，保持四语言 key 集合一致。

### 3.5 Mock 数据与测试

- Mock 数据层为规则行的观察模式状态由页面本地 `observeModes` 状态承载，覆盖开启和关闭两种状态，便于前端联调和视觉验证。
- 已有单元测试覆盖列表 Switch 渲染路径（`BehaviorControlTable.test.tsx`），后续如涉及抽屉回填/保存逻辑变更需同步补充抽屉侧测试。

## 7. 关联功能模块变更

### 7.1 规则效能统计——发信行为管控规则效能口径

- **需求背景**：发信行为管控规则支持观察模式后，需要在"规则效能统计"模块中看到该模块下规则的效能表现（命中量、动作分布、观察时长等），并支持从效能明细跳转回邮件处置中心查看命中详情。
- **实现内容**：`src/lib/mock/rule-effectiveness-prototype.ts` 中已包含 `behavior_control` 模块类型（`policy_module: 'behavior_control'`）、跳转路径映射（`config_path.behavior_control`）以及该模块的可执行动作口径（`reject`/`discard`/`quarantine`/`audit`）；`src/components/statistics/rule-effectiveness/constants.ts` 中已包含该模块的筛选项与专属配色（`#0EA5E9`）。
- **涉及文件**：`src/lib/mock/rule-effectiveness-prototype.ts`、`src/components/statistics/rule-effectiveness/constants.ts`。

### 7.2 邮件处置中心——上下文提示条对发信行为管控的兼容修复（缺陷修复）

- **问题现象**：在"规则效能统计"模块中，点击发信行为管控规则的"命中详情"跳转到邮件处置中心后，页面顶部未渲染来源上下文提示条，也没有可用的"返回"按钮返回规则效能统计页面。
- **根因**：
  1. `RuleEffectivenessContextBanner` 组件用于判断是否渲染提示条的模块白名单最初未包含发信行为管控对应的 `policy_key` 取值，导致命中该模块时组件直接返回 `null`。
  2. 规则效能统计跳转到处置中心时，发信行为管控模块使用的 `policy_key` 实际取值为大写标识 `BEHAVIOR`（而非其余模块使用的下划线小写命名，如 `sender_filter`），白名单补充时需要按实际传参值匹配，而非按模块的 `policy_module` 命名习惯猜测。
- **修复方案**：
  1. 在 `RuleEffectivenessContextBanner` 的模块白名单中加入 `'BEHAVIOR'`，使该 `policy_key` 命中时提示条正常渲染。
  2. 对 `policy_key === 'BEHAVIOR'` 的情况，与 `sender_filter` 采用相同的路径展示策略：直接取 URL 上的 `strategy_name` 查询参数作为路径文本展示（不走多级策略路径拼接），并展示 `observe_window_from`~`observe_window_to` 的观察起始时间区间。
  3. "返回"按钮逻辑不变：若浏览历史可回退则调用 `router.back()` 返回规则效能统计页面，否则直接跳转到 `/statistics/rule-effectiveness`。
- **验证**：已在浏览器预览中验证——从规则效能统计模块点击发信行为管控规则的"命中详情"，跳转到邮件处置中心后顶部正常展示来源上下文提示条（模块路径、观察时间区间），点击"返回"按钮可正常回到规则效能统计页面。
- **涉及文件**：`src/components/email-disposal/rule-effectiveness-context-banner.tsx`。
- **未变更声明**：`src/components/email-disposal/lib/disposal-detail-api.ts`、`src/components/email-disposal/sections/overview/entity-detection.tsx`、`src/components/email-disposal/hooks/use-detection-stages.ts` 等处置中心其他文件本次均未修改。
