# GT-13031 邮件处置中心-哈希加黑后缺少内容规则管理入口，无法定位已创建规则

## 1. 需求背景

邮件处置中心执行哈希加黑后，用户缺少进入内容规则管理页面的明确入口，无法快速定位或确认已创建的内容规则。内容规则模块已支持“附件哈希”作用域，本需求补充邮件处置中心到内容规则管理的可发现路径。

## 2. 最终实现方案

- 在邮件处置中心的哈希加黑结果或相关操作反馈区域，提供“内容规则管理”入口。
- 入口跳转至内容规则管理页面：`/zh/security/content-rules`，实际语言前缀沿用当前语言环境。
- 进入内容规则管理后，用户可查看已创建规则，并通过规则名称、作用域、匹配内容和执行动作确认哈希加黑对应规则。
- 内容规则管理页面继续使用项目现有的国际化框架，不新增硬编码中文。
- 保留现有哈希加黑、规则创建、规则编辑、删除和其他邮件处置能力，不改变既有接口和权限边界。

## 3. 功能路径

邮件处置中心 → 哈希加黑 → 内容规则管理 → 查看已创建规则。

## 4. 截图事实源

用户提供的内容规则截图显示：

- 内容规则新建页面支持“附件哈希”作用域。
- 右侧“当前配置效果”能够展示“作用于：主题、正文、附件哈希”。
- 因此邮件处置中心的哈希加黑操作应能通过内容规则管理入口定位到该类规则。

## 6. 待确认项

- 入口具体展示位置：哈希加黑成功提示、操作结果详情，或邮件处置记录详情。
- 是否需要进入内容规则管理后自动带入筛选条件，以直接定位当前哈希对应规则。
- 哈希匹配采用的算法和展示格式沿用现有后端契约。

## 7. 变更范围

本需求涉及邮件处置中心与内容规则管理之间的导航和规则定位体验。除入口、跳转和定位所需的展示逻辑外，不扩展其他安全策略模块。
