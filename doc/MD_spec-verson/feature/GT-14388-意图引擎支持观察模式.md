# GT-14388 意图引擎支持观察模式

## 1. 需求背景

意图引擎按照收信、发信、域内三个方向识别色情/赌博、政治敏感、仿冒/钓鱼、垃圾信息、订阅类信息等意图，并依据配置执行放行、继续投递、隔离、审核或丢弃。

在规则正式执行前，管理员需要先观察规则的命中情况、风险分布和潜在处置结果。如果直接启用正式处置动作，可能误伤正常邮件，也可能因为阈值配置不合理造成漏检。本需求为意图引擎增加按意图粒度控制的“观察模式”：启用后继续执行意图识别和命中记录，但不按照该意图的正式处置动作改变邮件最终结果。

本需求同时补齐规则效能统计和邮件处置中心的关联展示，使管理员可以从配置页进入统计、从统计进入邮件详情，并在邮件处置中心识别观察命中及返回来源页面。

## 2. 需求目标

- 在意图引擎每个“方向 × 意图类型”配置卡片上提供独立观察模式开关。
- 观察模式与意图启用状态、检测模式、处置动作、阈值区间和邮件标记配置相互独立。
- 支持收信、发信、域内三个方向，以及五种意图类型。
- 支持分类模式和分段阈值模式下的观察命中记录。
- 在规则效能统计中展示意图引擎的观察数据，并提供独立模块筛选。
- 在邮件处置中心展示观察命中状态、来源策略路径和观察时间区间，并支持返回规则效能统计。
- 本文档仅描述 GT-14388 相关实现，不改变其他安全策略模块既有功能。

## 3. 功能范围

### 3.1 覆盖对象

| 维度 | 可选值 |
| --- | --- |
| 邮件方向 | 收信、发信、域内 |
| 意图类型 | 色情/赌博、政治敏感、仿冒/钓鱼、垃圾信息、订阅类信息 |
| 观察状态 | 关闭、开启 |
| 检测模式 | 分类优先、分段阈值 |
| 统计模块 | 意图引擎 |

### 3.2 不在本需求范围内

- 不修改其他安全策略模块的观察模式逻辑。
- 不新增独立的意图引擎规则列表页。
- 不改变已有分类动作和阈值动作的配置含义。
- 不改变邮件处置中心原有筛选、分页、详情和处置操作。
- 不新增与本需求无关的后端接口或数据表。

## 4. 配置数据模型

### 4.1 意图引擎总配置

配置对象由三个方向组成，每个方向包含五个意图配置：

```ts
interface IntentEngineConfig {
  engine_enabled: {
    receive: boolean;
    send: boolean;
    internal: boolean;
  };
  directions: {
    receive: IntentDirectionConfig;
    send: IntentDirectionConfig;
    internal: IntentDirectionConfig;
  };
}
```

### 4.2 单个意图配置

每个意图配置包含以下字段：

```ts
interface IntentSingleConfig {
  enabled: boolean;
  observe_mode: boolean;
  action: IntentAction;
  mark_config?: IntentMarkConfig;
  detection_mode: 'classification' | 'threshold';
  threshold_segments?: ThresholdSegment[];
}
```

字段规则：

- `enabled`：控制该意图是否参与检测。
- `observe_mode`：控制该意图命中后是否进入观察处理。
- `action`：分类模式下的正式处置动作。
- `detection_mode`：控制使用分类动作还是阈值区间动作。
- `threshold_segments`：阈值模式下的置信度区间和对应动作。
- `mark_config`：继续投递动作使用的主题或邮件头标记配置。

### 4.3 默认值

- 新配置的 `observe_mode` 默认值为 `false`。
- 新配置的 `enabled` 默认值为 `true`。
- 默认检测模式为 `classification`。
- 高风险意图默认动作按方向生成：收信默认隔离，发信和域内默认丢弃。
- 中风险意图收信默认隔离，发信和域内默认审核。
- 低风险意图默认继续投递。
- 阈值模式默认生成覆盖 `[0, 1]` 的连续区间。

## 5. 意图引擎页面实现

实现文件：

- `src/components/security/intent-engine/IntentEnginePage.tsx`
- `src/components/security/intent-engine/IntentCard.tsx`
- `src/components/security/intent-engine/defaults.ts`
- `src/types/intent-engine.ts`
- `src/lib/api/intent-engine.ts`

### 5.1 打开意图引擎页面

1. 用户进入安全策略流水线的意图引擎阶段。
2. 页面调用 `GET /security/intent-engine` 获取配置。
3. 返回数据经过兼容归一化：缺少检测模式时补为分类模式，缺少阈值区间时按方向和风险等级补齐默认区间。
4. 页面展示方向页签，默认选中“收信方向”。
5. 当前方向下按风险等级展示五张意图卡片。
6. 每张卡片展示意图名称、风险等级、检测模式、处置动作、观察模式开关和展开箭头。

### 5.2 切换邮件方向

1. 用户点击“收信方向”“发信方向”或“域内方向”页签。
2. 页面将当前 `direction` 设置为对应值。
3. 页面读取 `config.directions[direction]`。
4. 页面关闭当前已展开的意图卡片，避免把上一方向的展开状态带到新方向。
5. 页面展示目标方向下五个意图的独立配置。
6. 未保存修改按现有脏状态规则保留；方向切换不自动提交接口。

### 5.3 开启观察模式

1. 用户在某张意图卡片右侧点击“观察模式”开关。
2. 组件阻止点击事件冒泡，避免同时触发展开/收起卡片。
3. 当前意图配置的 `observe_mode` 更新为 `true`。
4. 开关立即显示开启状态。
5. 页面标记当前方向存在未保存修改。
6. 页面不修改该意图的 `enabled`、`action`、`detection_mode`、阈值区间或标记配置。
7. 页面不立即调用保存接口。
8. 如果当前意图已关闭，观察模式开关不可操作；先启用意图后才允许开启观察模式。

### 5.4 关闭观察模式

1. 用户点击已开启的“观察模式”开关。
2. 当前意图配置的 `observe_mode` 更新为 `false`。
3. 开关立即显示关闭状态。
4. 页面标记当前方向存在未保存修改。
5. 已配置的正式动作、检测模式、阈值区间和标记配置保持不变。
6. 关闭观察模式不会关闭该意图本身。

### 5.5 展开意图卡片

1. 用户点击意图卡片头部的非配置控件区域，或使用键盘 Enter/Space。
2. 卡片在展开和收起之间切换。
3. 展开后展示检测模式、正式动作或阈值区间配置。
4. 观察模式开关仍固定在卡片头部，用户无需展开卡片即可切换。
5. 当意图关闭时，卡片内容保持可见但降低视觉强调，并禁止修改内部配置。

### 5.6 配置分类优先模式

1. 用户展开意图卡片。
2. 在“检测模式”区域选择“分类优先”。
3. 页面显示单一正式动作下拉框。
4. 用户选择放行、继续投递、隔离、审核或丢弃。
5. 选择继续投递时展示主题标记和邮件头标记配置。
6. 选择其他动作时清理不适用的标记配置。
7. 若该意图处于观察模式，分类动作仍作为“观察命中后的预期动作”保存，但观察期间不直接执行。

### 5.7 配置分段阈值模式

1. 用户展开意图卡片。
2. 在“检测模式”区域选择“分段阈值”。
3. 页面展示当前阈值区间、区间动作和区间可视化条。
4. 用户可新增、编辑、删除阈值区间。
5. 页面实时校验区间是否从 `0` 开始、到 `1` 结束、无间隙且无重叠。
6. 存在间隙时提示未完整覆盖；存在重叠时提示区间重叠。
7. 若任一阈值区间动作为继续投递，展示标记配置。
8. 若该意图处于观察模式，阈值动作仅作为观察结果中的预期动作，不直接改变邮件最终处置。

### 5.8 保存配置

1. 用户点击页面保存按钮。
2. 页面遍历收信、发信、域内三个方向的全部意图配置。
3. 页面校验所有阈值模式配置，任一方向任一意图存在间隙或重叠时阻止保存。
4. 页面为已启用但文案为空的主题标记或邮件头标记补齐默认文案。
5. 页面调用 `PUT /security/intent-engine` 提交完整 `IntentEngineConfig`。
6. 接口成功后，将提交后的配置写回页面状态。
7. 页面清除所有方向的未保存标记和复制反馈。
8. 页面提示保存成功。
9. 接口失败时保留当前编辑内容，不清除未保存标记，并展示失败原因。

### 5.9 复制与重置

#### 复制到其他方向

1. 用户在当前意图卡片执行“复制到其他方向”。
2. 用户选择一个或多个目标方向。
3. 页面深拷贝当前方向的完整意图配置，避免阈值区间或标记配置共享引用。
4. 目标方向配置发生变化时标记对应目标方向为未保存。
5. 目标方向配置已完全一致时不标脏，并提示无需修改。
6. 页面提示已复制到哪些方向，复制结果需保存后生效。

#### 应用同风险等级配置

1. 用户在意图卡片中执行“应用同风险等级”。
2. 页面根据当前意图风险等级查找同风险等级的其他意图。
3. 页面将当前意图配置深拷贝到同风险等级意图。
4. 页面仅更新当前方向配置，并标记当前方向未保存。
5. 页面提示应用成功。

#### 重置当前方向

1. 用户点击重置当前方向。
2. 页面弹出重置确认对话框。
3. 用户确认后，页面使用当前方向默认配置替换该方向的全部意图配置。
4. 所有意图的 `observe_mode` 恢复为 `false`。
5. 页面标记当前方向未保存，必须点击保存后才提交。
6. 用户取消时不改变任何配置。

## 6. 观察模式处理规则

### 6.1 分类模式

1. 邮件进入意图引擎。
2. 引擎按当前方向执行对应意图识别。
3. 未命中意图时，继续后续检测流程。
4. 命中且 `observe_mode = false` 时，按 `action` 执行正式处置。
5. 命中且 `observe_mode = true` 时，记录观察命中、意图类型、方向、预期动作和命中信息。
6. 观察命中不直接执行隔离、丢弃、拒收或其他阻断动作。
7. 邮件继续进入后续检测和最终裁决流程。
8. 处置中心将该检测阶段标记为 `observed`，并使用观察状态图标和颜色。

### 6.2 分段阈值模式

1. 邮件进入意图引擎并计算意图置信度。
2. 引擎根据置信度匹配唯一阈值区间。
3. 未命中意图时，继续后续检测流程。
4. 命中且 `observe_mode = false` 时，执行命中区间配置的正式动作。
5. 命中且 `observe_mode = true` 时，记录命中区间、置信度、区间动作和观察结果。
6. 观察模式不改变区间动作配置本身，区间动作作为“预期处置动作”展示。
7. 邮件处置中心展示观察状态，不将该阶段直接标记为威胁或阻断。

### 6.3 与模块总开关的关系

- 意图引擎模块关闭时，不执行意图引擎检测，方向配置中的观察模式不生效。
- 意图引擎模块开启但单个意图关闭时，该意图不执行检测，观察模式开关不可用。
- 模块总开关、方向配置和单个意图开关均需满足启用条件后，观察模式才参与运行。

## 7. 规则效能统计关联变化

### 7.1 模块定义

规则效能统计新增独立模块 `intent_engine`，不再将意图引擎数据归入“内容规则”。

涉及实现：

- `src/lib/api/rule-effectiveness-view.ts`：`PolicyModule` 增加 `intent_engine`。
- `src/components/statistics/rule-effectiveness/constants.ts`：增加模块类型、筛选值、模块颜色和策略路径键。
- `src/components/statistics/rule-effectiveness/FilterBar.tsx`：增加“意图引擎”中文筛选项。
- `src/components/statistics/rule-effectiveness/RuleEffectivenessPage.tsx`：增加意图引擎配置跳转路径。
- `src/lib/mock/fixtures.ts`：提供 15 条意图引擎 mock 统计记录。

### 7.2 Mock 数据范围

mock 数据按三个方向和五种意图组成 15 条记录：

- 收信方向：5 条。
- 发信方向：5 条。
- 域内方向：5 条。
- 每条记录包含策略标识、策略名称、观察起始时间、观察天数、邮件数、预期处置动作和动作分布。

### 7.3 查看意图引擎统计数据

1. 用户进入“规则效能统计”。
2. 用户打开策略模块筛选器。
3. 用户选择“意图引擎”。
4. 页面将筛选参数设置为 `intent_engine`。
5. 页面只展示 `policy_module = 'intent_engine'` 的记录。
6. 用户可查看观察期、邮件数量、命中结果、动作分布和效果摘要。
7. 用户清除筛选后，意图引擎记录与其他模块记录按统一表格口径展示。

### 7.4 从统计详情跳转策略配置

1. 用户在意图引擎统计表中点击某条记录的“前往策略配置”。
2. 页面优先使用记录中的具体配置路径；没有具体路径时使用意图引擎模块兜底路径。
3. 跳转地址携带意图引擎模块标识和 `source=rule_effectiveness`。
4. 目标页面定位到安全策略流水线的意图引擎阶段。
5. 若记录包含方向和意图标识，目标页面应按深链参数定位对应方向和意图卡片。
6. 页面展示来源上下文，并提供返回规则效能统计入口。

### 7.5 从统计详情跳转邮件处置中心

1. 用户在统计表某条意图引擎记录上点击“查看命中详情”。
2. 页面生成处置中心查询参数，包括 `source=rule_effectiveness`、`policy_key=intent_engine`、策略名称、子策略标识及观察时间范围。
3. 邮件处置中心读取参数并展示对应筛选结果。
4. 页面顶部显示规则效能统计来源上下文提示条。
5. 提示条显示“意图引擎 / 方向 / 意图类型”策略路径和观察时间区间。
6. 用户点击“返回”时优先调用浏览器历史回退；无法回退时跳转规则效能统计首页。

## 8. 邮件处置中心关联变化

涉及实现：

- `src/components/email-disposal/sections/analysis-section.tsx`
- `src/components/email-disposal/hooks/use-detection-stages.ts`
- `src/components/email-disposal/sections/overview/threat-summary-card.tsx`
- `src/components/email-disposal/rule-effectiveness-context-banner.tsx`
- `src/components/email-disposal/lib/disposal-basis-config.ts`

### 8.1 观察命中状态展示

1. 邮件详情加载检测阶段结果。
2. 意图引擎命中且处于观察模式时，检测阶段状态为 `observed`。
3. 分析区域使用观察状态图标，不使用威胁状态图标。
4. 阶段卡片使用观察状态颜色，避免与正式阻断、威胁和可疑状态混淆。
5. 命中策略行展示观察结果和预期处置动作。
6. 观察命中不被汇总为已执行的隔离、丢弃或拒收动作。
7. 邮件整体最终裁决仍以其他检测阶段和正式处置结果为准。

### 8.2 观察命中详情字段

观察命中详情至少展示：

- 检测模块：意图引擎。
- 邮件方向：收信、发信或域内。
- 意图类型：五种意图之一。
- 当前状态：观察中/已观察。
- 命中置信度；阈值模式下同时展示命中的区间。
- 预期处置动作：按分类动作或阈值区间动作读取。
- 观察时间或观察窗口。
- 规则效能统计来源信息（存在深链参数时）。

### 8.3 规则效能上下文提示条

1. 处置中心读取 URL 的 `source`、`policy_key`、`sub_strategy`、`strategy_name`、`observe_window_from` 和 `observe_window_to`。
2. 仅当 `source=rule_effectiveness` 且策略参数完整时渲染提示条。
3. `policy_key=intent_engine` 时允许通过模块白名单校验。
4. 意图引擎路径按“意图引擎 / 方向 / 意图类型”展示；若缺少细分路径，则使用策略名称兜底。
5. 存在观察窗口时展示起止日期。
6. 提示条右侧展示“返回”按钮。
7. 点击“返回”时优先执行 `router.back()`；无可回退历史时跳转 `/{locale}/statistics/rule-effectiveness`。
8. 未携带规则效能来源参数时不显示该提示条，不改变处置中心原有布局。

### 8.4 与现有处置中心功能的边界

- 不改变处置中心邮件列表查询接口。
- 不改变处置中心原有威胁汇总、检测阶段、原始日志和后置处理功能。
- 不改变其他策略模块的来源上下文展示。
- 观察状态只增加状态识别和来源展示，不增加处置中心的二次处置按钮。

## 9. 国际化要求

- 意图引擎观察模式标签使用 `intentEngine.observeMode.label`。
- 观察模式提示使用 `intentEngine.observeMode.hint`。
- 观察命中状态使用现有 `observed` 状态文案，不新增同义重复文案。
- 规则效能统计模块名称使用“意图引擎”。
- 处置中心来源提示、观察起始时间和返回按钮使用现有 `emailDisposal.ruleEffectivenessContext` 命名空间。
- 所有新增 key 应同步维护中文、英文、俄文、泰文资源，保持 key 集合一致。
- 文案使用 UTF-8 编码，不引入 Unicode replacement character 或异常乱码。
