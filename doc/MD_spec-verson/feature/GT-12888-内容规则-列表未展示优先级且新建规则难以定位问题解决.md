# GT-12888
## 内容规则-列表未展示优先级且新建规则难以定位问题解决

- **文档类型**：增量需求文档
- **关联总工单**：GT-13017【0818】处理问题总工单
- **页面范围**：阶段3：内容层 / 内容规则
- **页面路由**：`/zh/security/content-rules`
- **实现文件**：`src/components/security/content-rules/ContentRulesTable.tsx`
- **生成日期**：2026-08-18

## 1. 问题背景

内容规则列表此前缺少“优先级”字段，用户无法直接根据优先级判断规则执行顺序；新建规则后也难以在列表中快速定位和核对该规则的优先级信息。

## 2. 需求目标

在内容规则列表中展示“优先级”列，并将其放置在“状态”列之前，使规则 ID、规则名称、匹配类型、动作、范围、优先级、状态等信息形成稳定的核对路径。

## 3. 最终方案

1. 在列表列定义中增加 `priority` 列。
2. 列标题通过国际化框架读取 `contentRules.priority`，不在组件内硬编码中文。
3. 单元格读取 `row.original.rule.priority`，使用项目既有字体与语义样式展示数值。
4. 列顺序为：范围 → 优先级 → 状态 → 生效时间 → 操作。
5. 不修改新建规则流程、保存接口、排序逻辑、筛选逻辑或其他功能模块。

## 4. 验收标准

- 内容规则列表可见“优先级”列。
- “优先级”位于“状态”之前。
- 新建规则保存后，列表能够展示该规则的优先级数值，便于定位和核对。
- 中文文案通过项目国际化框架提供，UTF-8 编码正确，不出现 `�`。
- 既有列、操作、分页、筛选和数据请求行为不发生变化。

## 5. 依据与验证

- 用户提供的页面截图：内容规则列表包含“优先级”列，且位于“状态”之前。
- webapp 当前实现：`ContentRulesTable.tsx` 使用 `contentRules.priority` 和 `row.original.rule.priority`。
- 乱码自检：已对本次修改文件执行 `�` 字符搜索，结果为 0。

## 6. 变更范围

仅涉及内容规则列表的展示列与对应需求文档；不扩展到附件安全检测、URL 检测与防护、意图引擎或其他功能模块。
