# 对话级功能优化记录生成技能

## 职责

在一次对话或迭代阶段结束后，将本次对话中涉及的**所有功能优化模块**汇总为一份结构化静态 HTML 变更记录文档，输出到：

```text
webapp/doc/html-spec/changelogs/
```

每个优化条目必须包含：

- **功能路径**：页面路由 + 模块名称，例如 `邮件处置 / 处置设置 / 隔离区设置`；
- **本次优化点**：本次对话中具体改动了什么，精确到交互、校验、布局、文案、逻辑等维度；
- **影响的关联模块**：此次改动直接或间接影响到的其他页面、组件、i18n 文件、API、schema 等；
- **变更类型**：使用标准标签（见下方类型表）；
- **涉及源码文件**：列出本次变更实际修改的文件相对路径。

本技能只生成变更记录文档，不生成完整页面规格，不截图，不修改 `webapp/src/`，也不自动提交代码。

与 `html-spec-generator` 技能的区别：

| 维度 | html-spec-generator | html-spec-PM-version（本技能） |
|---|---|---|
| 触发时机 | 需要完整页面规格时 | 对话/迭代结束，做阶段性归档 |
| 内容范围 | 单个模块的全量规格 | 本次对话所有涉及模块的变更摘要 |
| 核心信息 | 截图 + 交互 + 元素详细表 | 功能路径 + 优化点 + 影响模块 |
| 读者 | 开发 / 测试 | PM / 产品经理 / 复盘归档 |

---

## 触发条件

用户提出以下请求时使用本技能：

- 生成本次对话的变更记录 / 优化日志；
- 生成 PM 版规格 / 对话总结文档；
- 汇总本次改动，归档迭代；
- `html-spec-PM-version`。

---

## 变更类型标签

每个优化条目必须标注一个或多个类型标签：

| 标签 | 含义 |
|---|---|
| `[布局优化]` | 页面结构、间距、响应式调整 |
| `[交互改进]` | 操作流程、状态反馈、导航行为优化 |
| `[校验增强]` | 新增或修复前端/后端校验逻辑 |
| `[错误处理]` | 错误消息本地化、异常兜底、Toast 优化 |
| `[权限控制]` | 字段可见性、禁用条件、权限依赖关系 |
| `[i18n]` | 新增/修改国际化文案 |
| `[可用性]` | 防误操作、提示引导、未保存确认等 |
| `[性能]` | 渲染优化、请求减少、加载改善 |
| `[缺陷修复]` | 修复已知 Bug |
| `[架构]` | Context、Hook、Schema、数据流调整 |

## 信息来源与提取规则

### 来源优先级

1. **本次对话内容**（最高优先级）：从对话记录中逐条提取用户描述的问题现象、预期结果及实现决策；
2. **当前 git diff / 已修改文件列表**：通过 `git diff --name-only HEAD` 获取本次实际变更文件；
3. **源码**：用于确认影响范围，补充模块间依赖关系；
4. **历史对话文件**（`user_read_only_context/conversation_history/`）：当上下文被压缩时，从历史文件中补充早期对话内容。

### 提取规则

- **不虚构**：只记录对话中明确提及、已实现或已讨论的改动，不推断"可能还改了什么"；
- **不遗漏**：本次对话中每一个被明确触及的功能模块，都必须出现在变更记录中；
- **粒度适当**：一个功能模块下的多个小改动合并为一条条目，不逐行列代码；
- **影响模块必须具体**：不写"影响相关组件"，要写具体的文件名或模块名，例如 `quarantine-settings-tab.tsx`、`messages/zh.json`；
- **历史对话截断时**：明确写"历史对话部分已截断，以下条目基于可获得上下文"，不伪造未见内容。

## 输出目录与文件命名

```text
webapp/doc/html-spec/changelogs/
├── index.html                        # 变更记录总索引（按日期倒序）
└── YYYY-MM-DD-<对话摘要>.html        # 本次对话变更记录
```

文件命名规则：
- 日期使用实际生成日期（`YYYY-MM-DD`）；
- `<对话摘要>` 取本次对话的核心主题关键词，使用英文短横线连接，例如：`disposal-settings-guard-and-validation`；
- 不使用 `version-N` 作为文件名，版本号由内容中的条目序号体现。

## 必备章节与结构

每份变更记录 HTML 必须包含以下章节，按序排列：

### 1. 文档元信息

```
对话日期：YYYY-MM-DD
生成时间：YYYY-MM-DD HH:MM
对话主题：（一句话概括本次对话核心目标）
涉及模块总数：N 个
变更条目总数：N 条
git 当前分支：（从 git rev-parse --abbrev-ref HEAD 获取）
```

### 2. 变更概览表

一张总表，每行对应一个功能模块：

| # | 功能路径 | 变更类型 | 优化点摘要 | 影响模块数 |
|---|---|---|---|---|
| 1 | 邮件处置 / 处置设置 / 隔离区设置 | [布局优化][i18n] | 分类通知列表改为紧凑表格 | 3 |
| … | … | … | … | … |

### 3. 逐条变更详情

每个功能模块一个 `<section>`，结构如下：

```
### [条目序号] 功能路径

**页面路由**：/zh/路由路径
**变更类型**：[标签1][标签2]

#### 本次优化点
- 优化点 1（精确描述改了什么，达到了什么效果）
- 优化点 2
- …

#### 影响的关联模块
| 模块/文件 | 影响类型 | 说明 |
|---|---|---|
| src/components/…/xxx.tsx | 直接修改 | 主要改动文件 |
| messages/zh.json | 新增 i18n 键 | 新增 3 个键 |
| src/contexts/…/yyy.tsx | 新增文件 | 新增 Context |
| … | … | … |

#### 设计决策与背景（可选）
如果本次优化背后有重要的技术选型或产品决策，在此简述，方便后续复盘。
```

### 4. 本次对话未解决事项

记录本次对话中提及但**未完成**或**标记为待确认**的问题：

| # | 问题描述 | 状态 | 备注 |
|---|---|---|---|
| 1 | … | 待处理 / 已提出但未实现 | … |

无未解决事项时写：「本次对话无未解决事项。」

### 5. 版本历史

记录 `changelogs/` 目录下所有已生成文档的摘要，最新在前：

| 日期 | 文件 | 对话主题摘要 | 条目数 |
|---|---|---|---|
| 2026-07-29 | 2026-07-29-disposal-settings-guard.html | 处置设置未保存拦截与权限校验 | 5 |
| … | … | … | … |

## 工作流

### Phase 0：收集本次对话范围

1. 从当前上下文提取本次对话中所有被讨论或实现的功能改动；
2. 读取历史对话文件（如有）补充早期改动：
   ```bash
   ls user_read_only_context/conversation_history/
   ```
3. 执行 git 命令获取实际变更文件列表：
   ```bash
   cd webapp && git diff --name-only HEAD~1 HEAD 2>/dev/null || git status --short
   ```
4. 对照对话内容与 git diff，确认范围，识别遗漏。

### Phase 1：按模块归类整理

1. 将所有改动归类到功能模块（一个模块 = 一条变更详情条目）；
2. 同一次对话中对同一模块的多轮修改合并为一条；
3. 对每个模块提取：功能路径、优化点列表、涉及文件、变更类型标签；
4. 识别跨模块的关联影响（例如新建 Context 影响多个页面）。

### Phase 2：生成 HTML 文档

1. 确认 `webapp/doc/html-spec/changelogs/` 目录存在，不存在则创建；
2. 读取已有 `changelogs/index.html`（如存在）中的版本历史；
3. 按上述章节结构生成本次变更记录 HTML 文件；
4. 更新 `changelogs/index.html`，在版本历史表顶部插入本次记录；
5. 不生成截图，不截图，不引用 webapp 组件 HTML。

生成的 HTML 必须：
- 内嵌文档 CSS，不依赖外部框架；
- 不包含任何 JavaScript 或可交互控件；
- 离线打开可完整阅读；
- 使用清晰的排版层次（h2/h3/table/ul）；
- 变更类型标签用 `<span class="tag tag-xxx">` 渲染为彩色标签；
- 功能路径使用面包屑样式 `A / B / C` 展示层级。

### Phase 3：验证文档完整性

逐条确认：
- 每个对话中涉及的功能模块都有对应条目；
- 每条条目都有功能路径、优化点、影响模块、变更类型；
- 影响模块列表具体到文件名，无"相关组件"等模糊描述；
- 未解决事项已列出；
- `changelogs/index.html` 版本历史已更新；
- 文档可离线打开且无残留交互控件。

## HTML 样式规范

变更记录文档使用以下内嵌 CSS 基准（可扩展，不得引用外部 CDN）：

```css
/* 变更类型标签配色 */
.tag { display:inline-block; padding:2px 8px; border-radius:4px; font-size:12px; font-weight:600; margin:2px; }
.tag-layout   { background:#dbeafe; color:#1d4ed8; }  /* 布局优化 */
.tag-ux       { background:#d1fae5; color:#065f46; }  /* 交互改进 */
.tag-validate { background:#fef3c7; color:#92400e; }  /* 校验增强 */
.tag-error    { background:#fee2e2; color:#991b1b; }  /* 错误处理 */
.tag-perm     { background:#ede9fe; color:#5b21b6; }  /* 权限控制 */
.tag-i18n     { background:#e0f2fe; color:#075985; }  /* i18n */
.tag-ux2      { background:#ecfdf5; color:#064e3b; }  /* 可用性 */
.tag-perf     { background:#f0fdf4; color:#14532d; }  /* 性能 */
.tag-fix      { background:#fdf2f8; color:#86198f; }  /* 缺陷修复 */
.tag-arch     { background:#f8fafc; color:#334155; }  /* 架构 */

/* 功能路径面包屑 */
.breadcrumb { color:#64748b; font-size:13px; }
.breadcrumb span { color:#94a3b8; margin:0 4px; }
```

## 关键约束

1. **只记录本次对话中明确发生的改动**，不推断、不补全未讨论内容；
2. **影响模块必须具体**，列到文件名或 i18n 键名级别；
3. **不生成截图**，不浏览器验证，不修改 `webapp/src/`；
4. **历史对话截断时必须标注**，不虚构早期内容；
5. **不自动提交或推送**；
6. **本技能不替代 `html-spec-generator`**，完整页面规格仍需调用后者。
