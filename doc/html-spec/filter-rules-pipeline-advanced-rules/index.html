5. 业务逻辑规格

5.1 条件合并语义

最终命中条件 = (OR组内条件任一命中) AND (AND组内条件全部命中)；任一组为空时仅取另一组。表达式预览实时输出等价表达式（见层级3）。

5.2 主附策略冲突矩阵（demo getAddonConflictRules L1143-1160，浏览器逐项实测一致）

执行动作被禁用的附加策略浏览器实测
不设置 / 投递 / 标记投递 / 邮件审核无限制（7 项全可勾选）✓
邮件隔离转发至目的服务器、更改信头（2 项置灰）✓ layer4-quarantine-conflict.png
丢弃 / 阻断仅「发送管理员通知」可用，其余 6 项置灰✓ layer4-block-params-conflict.png

5.3 保存校验

  • 确定按钮禁用条件：primaryAction==="none" 且无任何「已启用、未被冲突禁用、非 detailedLog」的附加策略（canSaveActions L3006）。实测：none + 全不勾 → 确定禁用 + 红字提示；勾选「发送管理员通知」→ 确定立即恢复。
  • 点击确定后校验：规则名称为空 →「规则名称不能为空」；作用范围全不选 →「请至少选择一个生效范围」——两者置红并强制跳回「基础设置」Tab（不禁用按钮）。
  • 保存成功：新建 push / 编辑按 id 替换 rules 数组，关闭抽屉，列表即时刷新。
