4. 数据模型与 API 映射

interface SenderFilterRule {
  id: string
  ruleId: string                 // 如 BL-20260320-001 / WL-20260320-001
  priority: number               // 黑名单默认 2000 起，白名单 2025 起，范围 2000-2049
  ruleName: string
  senderConfigType: "individual" | "group" | "organization"
  senderValue: string            // 个人邮箱（支持 *@domain.com）
  senderGroupId?: string
  senderGroupName?: string
  ipRangeType: "all" | "ipGroup" | "single" | "range"
  ipRangeValue?: string          // 单IP 或 CIDR
  ipGroupId?: string
  ipGroupName?: string
  action: "block" | "quarantine" | "review" | "allow"
  expireAt?: string              // 留空=永久
  remark?: string                // 最多 200 字
  enabled: boolean
  modifyTime: string
}
PRD API / 数据表用途落地映射建议需确认
GET /api/sender-filter/rules分页、搜索、类型筛选优先映射统一规则系统列表接口，用 type=blacklist/whitelist 区分页签。统一规则系统现有筛选字段是否覆盖 sender/ipRange。
POST/PUT/DELETE /api/sender-filter/rules规则增删改复用统一规则 CRUD；action 不新增，阻断/隔离/审核/放行映射现有动作。“审核 review”是否已有统一 action，或映射为隔离+人工队列标签。
PUT /api/sender-filter/rules/{id}/status切换启用/禁用复用统一规则启停接口。列表状态列需从只读 Badge 改为可操作开关（见差异）。
POST /api/sender-filter/simulate模拟测试可先前端本地模拟；如需真实匹配链路，提供统一规则 dry-run 接口。是否新增 dry-run API。
GET /api/sender-groups、/api/organizations、/api/ip-groups群组 / 组织 / IP 组下拉关联群组策略模块数据源。组织域名来源需与租户/组织通讯录统一。
t_sender_filter_rules / t_sender_filter_config规则表 / 全局配置表若统一规则系统已有表结构，避免新建独立规则表；ipRangeType 仍需存储。白名单全局策略（bypass_content/direct_deliver）落库位置。

5. 业务逻辑规格

逻辑PRD 要求demo 实际落地说明
匹配顺序白名单优先于黑名单；同类型 priority 升序；首个匹配生效；发信人+IP 组合都匹配才命中mock 数据分黑白名单，优先级区间黑名单 2000 起、白名单 2025 起后端规则引擎需明确白名单先行，不能仅依赖数值区间。
发信人类型个人邮箱、发信人群组、发信域名/组织抽屉 Select 三类，切换动态显示输入/下拉；列表用 User/Users/Building2 图标区分个人邮箱支持通配符 *@domain.com。
发信 IP 范围全部IP、IP组、单IP、IP段（CIDR）抽屉实现四类联动，列表未展示该列落地需补列表列或确认隐藏。
黑名单动作阻断、隔离、审核黑名单抽屉动作 Select 含三项阻断→reject/block；隔离→quarantine；审核需确认 action。
白名单动作允许；全局策略决定跳过内容检测(bypass_content)或直接投递(direct_deliver)白名单列表显示“放行”；源码有 globalExceptionMode 状态但无对应 UI需补白名单全局执行策略 UI，或确认移至流水线例外规则，见差异。
角色权限系统管理员全权；安全管理员不可删预置；审计员只读；普通用户无权限demo 未做权限态区分落地按统一权限矩阵控制按钮可见性。

列表缺“发信IP范围”列表格列含“发信IP范围”表格仅 7 列：规则ID、规则名称、发信人、执行动作、状态、修改时间、操作需确认是否补列；抽屉已支持 IP 范围配置。
抽屉区块数少于 PRD抽屉分 5 个色条区块：基本信息(蓝)/发信人配置(紫)/发信IP范围(青)/执行动作(红或绿)/其他配置(灰)实际只有 2 个色条区块：基础设置(蓝) + 执行动作(红)；备注在区块外，无紫/青/灰色条按 PRD 补齐分区色条，或确认合并布局。
发信人类型图标配色个人=蓝、群组=紫、组织=橙个人=灰(gray-500)、群组=蓝(blue-500)、组织=紫(purple-500)统一图标配色规范。
审核动作 Badge 颜色审核=紫（bg-purple-100）审核=黄（bg-yellow-100 text-yellow-700）确认最终配色。
状态呈现不是开关启用/禁用通过开关切换列表行内是只读 Badge（启用蓝/禁用灰），无开关控件；开关只在模块头（模块级启用）按 PRD 补行内 Switch；或只读视图需权限态说明。
删除确认未实现点击删除弹确认 AlertDialog删除图标存在但无 onClick，点击无反应落地需接线确认弹窗。
导入导出未接线支持导入 Dialog 与导出下载仅图标按钮，无 onClick，浏览器验证无弹窗/下载确认导入格式(CSV/JSON)和下载 API。
白名单全局配置缺 UI配置 bypass_content / direct_deliver源码有 globalExceptionMode 状态但页面未渲染任何配置区域确认放本模块还是统一例外规则。
