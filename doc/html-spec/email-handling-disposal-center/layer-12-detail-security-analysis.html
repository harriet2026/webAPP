1. 事后处置时间线 — 事件来源白名单过滤

1.1 方案概述

问题根因原过滤逻辑为黑名单（仅排除 event_source === 'postfix'），导致 antispam · policy_decided、antispam · quarantine_pending 等投递流程事件穿透过滤，错误出现在事后处置时间线中，且因这些值不在映射表中而渲染原始英文
修复方案改为白名单：DISPOSAL_SOURCES = new Set(['admin_api', 'threat_retro_agent'])，只保留两种事后处置来源的事件，其余（postfix / antispam 等）一律过滤
业务语义事后处置时间线只展示"事后处置动作"，不展示邮件投递/策略裁决流水
源码路径src/components/email-disposal/sections/analysis-section.tsx：DISPOSAL_SOURCES 常量 + disposalEvents useMemo 过滤

1.2 操作类型枚举（白名单内三种组合）

event_source event_type 中文显示（zh） 英文显示（en） 触发方式
admin_apirecall管理员召回Admin Recall管理员在详情页或列表页手动发起召回
threat_retro_agentrecall威胁回溯智能体发起召回Threat Retro Agent Recall威胁回溯智能体策略配置为 recall 时自动触发

i18n key（zh / en）：emailDisposal.detail.analysis.operationType.adminApiRecall / .threatRetroAgentRecall / .threatRetroAgentNotify；未命中时 fallback 到 event_type 原始值

2. 操作类型 — 由 event_source:event_type 复合键驱动 i18n

修复前展开事件详情后，「操作类型」值渲染 ev.event_type 原始英文（如 policy_decided、recall）
修复后调用 getOperationTypeLabel(ev.event_source, ev.event_type, t)，以 "source:type" 复合键查 OPERATION_TYPE_KEY_MAP，再通过 t() 读取 i18n 翻译；未命中时 fallback 原始 type 值
原因admin_api:recall 与 threat_retro_agent:recall 的 event_type 同为 recall，单字段翻译无法区分二者；需复合键
i18n keyemailDisposal.detail.analysis.operationType.{adminApiRecall | threatRetroAgentRecall | threatRetroAgentNotify}

3. 执行结果 — 操作成功与否的 i18n 映射

修复前「执行结果」值及行头 Badge 渲染 ev.event_result 原始英文（如 success、quarantine_pending）
修复后调用 getEventResultLabel(ev.event_result, t)，查 EVENT_RESULT_KEY_MAP 后通过 t() 读取翻译；Badge 同步使用该函数
语义边界event_result 只表示"本次操作是否成功"；邮件状态枚举（quarantine_pending、delivery_failed 等）属 MailLogDetail 层，不在此映射
