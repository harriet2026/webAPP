2.4 锁定提示弹窗 AlertDialog 条件

当点击 locked=true 的菜单项时弹出（radix AlertDialog）。标题 module.locked.title「功能未开通」、正文「请联系销售团队开通此功能模块权限」、确认按钮「我知道了」。

⚠️ 锁定来源有二：① 常量 LOCKED_MODULES = {"alert-notification"}；② resolveAccess 返回 locked（visibility=lock）。浏览器实测：5 形态 × 2 视角遍历，无任何菜单项渲染出锁定图标或触发弹窗——alert-notification 不在 navItems 中，且 AI_LOCK_LEGACY（唯一会产出 lock 的预设）在 FEATURES 中未被任何条目引用。详见 §8 差异。可交互预览中如需体验弹窗，可在浏览器 console 手动构造，或参考此处静态复刻：

3. 数据模型

侧边栏为纯前端配置驱动，无独立后端 API；导航树硬编码在 sidebar-nav.tsx，可见性由 product-profiles.ts 计算。

// NavItem —— 导航节点（sidebar-nav.tsx）
interface NavItem {
  id: string           // 与 FEATURE_MAP 对齐的功能 id
  labelKey: string     // i18n key（nav.*）
  icon?: ReactNode     // 仅 level 0 显示
  children?: NavItem[]
  href?: string
  locked?: boolean
  hidden?: boolean     // 不在侧边栏显示，但页面仍可访问
}

// 可见性解析（product-profiles.ts, resolveAccess）
function resolveAccess(id, form, viewer) {
  const vis = FEATURE_MAP[id].visibility[form]      // show | hide | lock
  const baseVisible = vis !== "hide", locked = vis === "lock"
  const isMulti = PRODUCT_FORMS[form].capabilities.multiTenant
  // 多租户 + 平台视角 + platformHidden → 对平台管理员隐藏
  if (feature.platformHidden && isMulti && viewer==="platform") return {visible:false}
  if (viewer==="platform" || !isMulti) return {visible:baseVisible, locked}
  switch (feature.tenantAccess) { "hidden"→隐藏; "readonly"→只读可见; "edit"→可见可编辑 }
}
导航树过滤（SidebarNav.navTree useMemo）：① FEATURE_MAP[id] 命中则按 resolve 决定去留，未命中（纯分组容器）默认保留；② 分组无 href 且可渲染子项（排除 hidden）为 0 → 整组收起；③ 多租户租户视角下 system-management 改名 nav.tenantSystemManagement「组织与成员」。

关键规则

  • 默认展开集合：{statistics, email-handling, system-management}（组件 useState 初值，硬编码）。
  • 激活判定：level 0 分组当自身或任一直接子项的 href 被 pathname.startsWith 命中即高亮；子项同理。
  • 单租户形态无「租户视角」概念，viewer 恒按 platform 处理（切到单租户会自动回退 platform）。
  • hidden 项（connection-layer / identity-strategy / content-strategy / comprehensive-strategy）永不在侧边栏渲染，但路由仍可直达。
  • 空分组自动收起：cloud/传统·多 + 平台视角下，安全策略 / 智能体中心 / 高管保护三组因子项全部 platformHidden 而整组消失。

8. 与源码 / spec 的差异标注

#差异点源码 / spec 预期浏览器实际渲染结论
1锁定弹窗 / 锁定图标不可达代码保留 LOCKED_MODULES、AI_LOCK_LEGACY、Lock 图标与 AlertDialog 全套逻辑5×2 遍历无任一项渲染锁定态：alert-notification 不在 navItems；AI_LOCK_LEGACY 在 FEATURES 未被引用死代码 / 保留钩子；落地保留即可，但需知当前无入口
2内置语言数implement.md：初始需支持四种内置语言demo 仅 zh / en / th 三种（language-switcher.tsx）落地补齐第 4 语言
3nav.systemStatus 文案语义不一致同一 key 应同义zh「系统状态」vs en「Home」/ th「หน้าแรก」翻译需对齐（确认以哪个为准）
4移动端响应式—无折叠 / 汉堡；始终 256px落地需补移动端策略
5hidden 项路由可直达hidden:true 仅不在侧栏显示connection/identity/content/comprehensive 页面仍可通过 URL 访问符合设计（记录备查）

9. 需确认事项

#问题背景
1锁定弹窗逻辑是否落地保留？入口如何设计？当前无任何菜单项触发锁定；若产品需要「售前升级钩子」，需明确哪些项在哪些形态下 lock
2第 4 种内置语言是哪种？implement.md 要求四语，demo 仅三语
3nav.systemStatus 最终文案（系统状态 / Home）？zh 与 en/th 语义不一致
4移动端 / 窄屏侧边栏是否需要折叠或抽屉？demo 无响应式折叠
5可见性矩阵是否作为落地实现的权威？后端是否需按 form/viewer 下发菜单？demo 为纯前端计算；网关侧需确认权限来源（避免仅前端隐藏）
