4. 业务逻辑规格

4.1 策略四档状态语义（spec §3.1 / demo renderConfigPanel）

状态标题语义备注（demo 常驻灰字）落地
inherit继承全局配置跟随全局设置，全局启用则启用、禁用则禁用；全局调整时本群组自动同步不写规则
enable强制启用本群组固定启用，不随全局变化；即使全局关闭仍保持启用钉死启用
disable禁用本群组固定禁用，不随全局变化；即使全局开启仍不检测钉死禁用
custom自定义参数/自定义子检查在全局默认基础上单独调整参数，仅对本群组生效覆盖参数；cloud 不支持（降级为强制启用）

4.2 执行顺序 vs 优先级（双轴模型，demo 核心）

模块执行顺序由阶段流水线（阶段1→阶段5）固定决定，与规则优先级无关；优先级（0000-0099，按项目权威定义数值越大越优先——CLAUDE.md）仅在多条策略命中同一封邮件、且配置了同一模块时用于仲裁。命中终态处置（隔离/拒绝/阻断/丢弃）即短路，后续阶段不执行——因此「优先级更高但模块位于更后阶段」的规则可能不生效（EffectivePathDialog 的 IP群组1 演示；该短路由阶段顺序决定，与优先级方向无关）。

⚠ 优先级方向冲突（务必以项目定义为准）：本项目权威定义为「优先级数值越大越优先」（CLAUDE.md），落地须据此实现——同模块冲突取数值最大者生效。demo 的说明条、优先级 Tooltip 及 EffectivePathDialog（升序 sort((a,b)=>a.priority-b.priority)、ignoredHigherPriority 用 r.priority < scPriority、winner 取较小值）均按「数值越小越优先」实现，与项目定义相反，属 demo 缺陷，落地须反转（见差异 #11）。本规格所有 verbatim 预览保留 demo 原文以便对照。

4.3 引用保护（群组管理）

群组 referenceCount>0 时删除按钮 disabled（spec §3.3 禁用删除 / TC-B05）；特征组删除额外做一次防御性校验（handleDeleteGroup）。
