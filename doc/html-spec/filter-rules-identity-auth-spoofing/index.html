1. 页面布局结构

「身份认证与仿冒检测」是收发信人策略页（/filter-rules/identity）左侧导航的第 2 个策略。选中后右侧渲染一张策略卡片：卡片头部是模块标题 + 启用状态 + 启用开关；卡片正文由 renderAuthSpoofingConfig() 输出，自上而下为「基础格式检查」Collapsible、「认证协议检查」Collapsible、（仅传统版）仿冒特征检测、底部「例外规则入口」。

4. 业务逻辑规格（以 spec 为准）

4.1 检查执行顺序

4.2 观察模式机制（spec §1.27-29）

开启后规则仅记录不执行阻断；可查看 7 天内观察统计；用于评估影响后再正式启用。demo 实现：开启时缓存当前动作到 xxxPrevAction 并把 UI 动作显示为只读「允许（仅记录）」，关闭时恢复缓存值。

4.3 策略模板语义（spec §1.14-18）

模板spec 语义Dialog 内说明文案（demo）
宽松大部分检查项设为「允许」，适合新部署测试仅拦截明确伪造，兼容老旧系统，丢弃动作使用极少
标准关键检查项设为「隔离」，平衡安全与可用性（推荐）平衡安全与业务，明确伪造使用阻断/丢弃，疑似伪造使用隔离
严格大部分检查项设为「阻断」，最高安全级别零信任策略，大量使用丢弃动作，适用于金融/政务等高安全场景
自定义用户自行配置各检查项动作完全手动控制，脱离模板保护，需自行评估风险
