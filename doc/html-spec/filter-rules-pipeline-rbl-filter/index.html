5. 业务逻辑规格（依据 spec 文档）

5.1 RBL 查询机制（spec §1 / §6）

  • 连接建立时提取发信 IP，对配置的所有 RBL 服务器并行发起 DNS 查询。
  • IP 反转拼接服务器域名（1.2.3.4 → 4.3.2.1.zen.spamhaus.org），查 A 记录；返回 127.0.0.x 判为命中，NXDOMAIN 为未命中。
  • 任一服务器命中即判定黑名单 IP；全部超时或未命中才放行（超时视为未命中）。
  • 结果缓存（Redis，TTL 默认 1 小时），目标缓存命中率 > 80%。
  • 性能目标：单服务器查询 < 100ms（P95），并行多服务器 < 200ms（P95），支持 20+ 服务器、10000 QPS。

5.2 命中动作语义

动作spec 语义网关落地
block 阻断返回 5xx 拒绝，邮件不会重试reject
quarantine 隔离放入隔离队列待审核quarantine
mark 标记加 X-RBL-Hit 邮件头，继续后续检测accept + add_headers
greylist 灰名单首次连接临时拒绝，重试后放行不支持（见 §9 D1 / §10 Q1）

5.3 灰名单模式（spec §1.4 / §6）

  • delay：首次连接返回临时拒绝，延迟 N 秒后允许重试。
  • rateLimit：在时间窗口内限制连接次数。
  • 通过灰名单后自动加入白名单，TTL 内不再检测；key 为三元组 (IP, 发信人域名, 收信人)，存首次连接时间。

5.4 权限矩阵（spec §1）

角色spec 权限demo 是否体现
系统管理员完整读写，可配置全部参数是（当前登录态即完整读写）
安全管理员可配置参数、查看统计否 demo 未做角色分支
审计员只读否 demo 无只读态

5.5 配置联动（spec §5）

  • 禁用 RBL 模块 → 跳过 RBL 检测环节。
  • 删除所有服务器 → 等同于禁用模块。
  • 选择灰名单动作 → 启用灰名单子模块配置（demo 已实现条件渲染）。
  • 群组策略：strategy-pipeline-page.tsx L98 声明 { key:"rbl", defaultEnabled:true, canExempt:true }，L128 示例 policyConfig:{ rblFilter:"exempt" } —— 即 RBL 支持按群组豁免。
