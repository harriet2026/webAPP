可用性 布局优化

邮件处置 / 处置设置 / 用户权限设置 · 外部访问地址校验

/zh/email-disposal/disposal-settings → Tab: 隔离区设置 → 用户权限设置卡片
校验增强 权限控制 i18n

本次优化点

  • 问题：外部访问地址（portal_base_url）为空时，前端仍允许开启取回、预览、加白、加黑权限并保存；四项权限依赖该地址生成通知链接，地址缺失时权限实际无效但无任何提示。
  • schema 层校验：在 disposalSettingsSchema 的 superRefine 中新增规则：若任意权限 enabled=true 且 portal_base_url 为空或非合法 http/https URL，则向该字段注入 ZodIssue，zodResolver 阻断 handleSubmit。
  • UI 禁用：实时派生 portalMissing（从 watch('quarantine.portal_base_url') 校验），地址缺失时四个 Switch 全部 disabled，整行 opacity-60 灰化，地址填写合法后自动恢复。
  • inline 警告横幅：地址缺失时在权限表上方渲染琥珀色 AlertTriangle 横幅，文案说明四项权限的依赖关系，引导管理员先填写地址再开启权限。
  • 字段级错误：保存校验失败时 portal_base_url 输入框高亮 border-destructive，下方显示中文错误提示。
  • 新增 i18n 键：portalBaseUrlRequired（字段级错误文案）、portalBaseUrlMissingHint（横幅提示文案）各 4 语言。

邮件处置 / 处置设置 · 后端错误消息本地化

/zh/email-disposal/disposal-settings → 保存操作 → 错误 Toast
错误处理 i18n

本次优化点

  • 问题：外部访问地址为空时开启权限并保存，页面 Toast 展示后端原始英文错误："quarantine.portal_base_url is required when the retrieve or preview permission is enabled…"，裸露字段名，不可理解。
  • 根因：disposal-settings-page.tsx 的 catch 块直接将 e.message（后端英文原文）传入 toast.error()，无任何翻译处理。
  • 修复：重构 catch 块，引入三级映射逻辑：① 含 portal_base_url 的 400 错误 → t('portalBaseUrlRequired')；② 含分类键名的 400 错误 → t('saveFailed')（并将错误标注到对应分类字段）；③ 其他错误 → 透传原始 message 或 t('saveFailed')。
  • setError 规范化：form.setError 的 message 统一改为键名字符串（如 'portalBaseUrlRequired'），与字段渲染层已有的 t(key) 模式保持一致，避免字段级提示和 Toast 文案不一致。

全局 · 处置设置未保存离开拦截

/zh/email-disposal/disposal-settings → 侧栏 SPA 跳转 / 浏览器关闭/刷新
可用性 架构 i18n

本次优化点

  • 问题：处置设置字段多且需滚动，管理员修改后未保存即点击侧栏跳转，所有改动丢失且无任何提示。
  • 新增 UnsavedGuardContext：新建 src/contexts/unsaved-guard-context.tsx，提供 registerGuard（注册 dirty 状态及保存回调）、unregisterGuard（卸载时清理）、requestNavigate（拦截跳转请求，有 dirty 时弹窗，无 dirty 时直接跳转）三个 API。
  • UnsavedGuardDialog：新建 src/components/layout/unsaved-guard-dialog.tsx，消费 Context，渲染 AlertDialog 弹窗，三个选项：「继续编辑」（关闭弹窗保持页面）、「放弃修改并离开」（直接跳转）、「保存后离开」（触发 form.handleSubmit 成功后跳转）。
  • AppShell 挂载：在 app-shell.tsx 中用 UnsavedGuardProvider 包裹整个布局，并在根层渲染 UnsavedGuardDialog，确保弹窗在所有页面路由切换时均可挂载。
  • 处置设置注册：disposal-settings-page.tsx 通过 useEffect 监听 form.formState.isDirty，变化时调用 registerGuard 同步最新状态；同时挂载 beforeunload 事件拦截浏览器关闭/刷新。
  • 侧栏拦截：sidebar-nav.tsx 中 SidebarNavItem 的 handleClick 将原 router.push(href) 替换为 requestNavigate(href, (href) => router.push(href))，所有侧栏跳转经 guard 过滤。
  • 自动清除 dirty：保存成功后 form.reset(saved) 重置 RHF 状态，isDirty 变为 false，guard 自动解除，不再误报。
  • 新增 i18n 键：unsavedChangesLeaveTitle、unsavedChangesLeaveDesc、keepEditing、discardAndLeave、saveAndLeave 共 5 键 × 4 语言，写入 common 命名空间。

设计决策与背景

Next.js 16 App Router 无 router.events，无法用框架内置机制拦截 SPA 导航。选择在 Context 层劫持 requestNavigate、在侧栏 handleClick 处拦截（而非全局 Link 或 pushState 劫持），原因是侧栏是本项目唯一的跨模块导航入口，改动范围最小、副作用最可控。UnsavedGuardContext 设计为通用架构，未来其他带表单的页面可通过相同的 registerGuard API 接入，无需修改 Context 或侧栏。
