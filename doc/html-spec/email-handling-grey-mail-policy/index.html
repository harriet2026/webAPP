4. 数据模型与 API 映射

4.1 前端数据模型（demo 原样提取）

interface GreyMailStrategy {
  id: string; name: string
  userGroup: "ALL" | "DEPT" | "GROUP"
  userGroupValue?: string; userGroupValues?: string[]   // 部门/用户多选
  mailTypes: string[]                                    // promo/subscribe/notify/social/member/meeting
  confidenceMin: number; confidenceMax: number          // 置信度区间 0-100
  action: string                                         // archive/mark/quarantine/delete/deliver
  priority: number; enabled: boolean; isDefault?: boolean
}
globalConfig { defaultConfidenceThreshold; autoCleanupDays; maxUserWhitelistSize; holidayMode }

4.2 处置动作 → 统一规则系统 action 映射（遵循 implement.md）

⚠️ 不新增 action。mark = accept + 添加特定 header（不是新 action）。archive/"归档至灰色文件夹"依赖邮件系统端 folder，网关侧需确认（见 §10）。
demo action文案建议映射
archive归档至灰色文件夹[需确认] 邮箱侧 folder / 或 accept+header 由客户端归类
mark标题标记[灰邮]accept + 添加 header（+ 主题标记）
quarantine隔离现有隔离动作
delete删除discard
deliver直投收件箱accept

5. 业务逻辑规格

5.1 策略匹配与优先级

邮件被判为灰邮后，按优先级（数值越大越优先，与统一规则系统一致）匹配策略：命中用户组 + 邮件类型 + 置信度落在 [min,max] 区间 → 执行该策略 action。内置策略（isDefault）不可删除，仅可启停/编辑。

flowchart TD A[邮件判定=灰邮, 得置信度] --> B{按优先级降序遍历策略} B --> C{用户组匹配?} C -->|否| B C -->|是| D{邮件类型匹配?} D -->|否| B D -->|是| E{置信度∈[min,max]?} E -->|否| B E -->|是| F[执行 action: archive/mark/quarantine/delete/deliver] B -->|无命中| G[默认放行/按全局阈值]

5.2 用户组作用域

userGroup文案取值UI
ALL全员默认-无附加选择
DEPT组织部门userGroupValues[](部门/用户 id) + userGroupValue(名称串)组织树多选（层级2）
GROUP群组userGroupValue(群组名)群组下拉单选（层级3）

5.3 增删改行为（demo 实测）

操作handler校验结果
新建handleAddStrategyname 必填（!name 直接 return）追加到 strategies，isDefault=false
编辑handleEditStrategy → handleUpdateStrategyname + editingStrategy 必填就地更新
删除handleDeleteStrategy仅非内置可删从 strategies 移除
启停handleToggleStrategy-enabled 取反
保存全部handleSave-console.log（demo 未持久化）
