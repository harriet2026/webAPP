4. 数据模型与 API 映射

type Direction = "receive" | "send" | "internal"
type ActionType = "isolate" | "review" | "block" | "discard" | "continue" | "pass" | "skipExceed"

interface AttachmentSecurityConfig {           // 按方向三份配置
  basicLimit: Record<Direction, BasicLimitConfig>
  antivirus: Record<Direction, AntivirusConfig>
  imageDetect: Record<Direction, ImageDetectConfig>
  encryptedAttachment: Record<Direction, EncryptedAttachmentConfig>
}
interface BasicLimitConfig { attachmentCountLimit; attachmentSizeLimit /*KB*/; nestedZipCountLimit;
  nestedFileCountLimit; nestedLevelLimit; scanTimeout /*s*/; exceedAction }
interface AntivirusConfig { enabled; primaryEngine: "qianxin"|"kaspersky"; backupEngine: "qianxin"|"kaspersky"|"none";
  autoSwitchOnFailure; dualEngineMode; virusAction; timeoutAction; engineStatus: {version, signatures, status}×2 }
interface ImageDetectConfig { ocrMode: "none"|"light"|"deep"; ocrLimit; qrMode: "none"|"light"|"deep";
  qrLightAction; qrBarcodeExempt; qrDeepRoute{Url,Keyword,Intent,Advanced}+子开关;
  qrDeepArbitration: "highest_priority"|"first_match"; qrDeepLimit(1-50); qrDeepExceedAction: "pass_warn"|"isolate" }
interface EncryptedAttachmentConfig { detectMode: "none"|"detect_only"|"deep"; decryptFailAction;
  extractFromBody; usePasswordBook; passwordBook: {password, addedAt}[]; recursiveDetect; markSuspicious }
PRD API / 数据表用途落地映射建议需确认
GET/PUT /api/config/attachment-security?direction=按方向读写配置 JSON走网关配置系统 ConfigManager（/apiserver.cf 或 antispam 配置节 + DB config_overrides 在线覆盖），不必新增独立配置表；方向作为配置路径的一级维度。配置粒度（租户×方向）与现有 config_overrides 模型的匹配方式（Q7）。
POST /api/antivirus/update?engine=、GET /api/antivirus/status病毒库更新/引擎状态网关现有深度附件扫描为 attachd 服务（cmd/attachd）；奇安信/卡巴斯基 ICAP 对接与病毒库状态接口当前不存在。[需确认] 新增引擎管理 API 或以 attachd 能力替代（Q3）。
GET/POST/DELETE /api/password-book密码本 CRUD（脱敏）需新增存储（PRD 建议 AES-256-GCM 加密列 + KMS；网关已有类似 OSG_DKIM_KEY_ENC_KEY 加密列先例）。[需确认] 新增表与 API；「全局共用」vs 租户隔离冲突（Q5）。
attachment_security_config / global_password_book / antivirus_engine_status 表产品设计表非硬性要求；配置走 config_overrides，密码本单独建表需同步所有信创 backend 的 init.sql。-
执行动作枚举isolate/review/block/discard/continue/pass/skipExceed复用统一规则系统 action：隔离→quarantine、阻断→reject、放行→accept；「审核」「丢弃」「进行下一步检测」「超出部分不检测」的映射见 Q4。[需确认] Q4

9. 与 PRD / 源码 / 浏览器渲染的差异标注

#位置PRD 描述demo 实际建议处理
D-1加密附件检测模式两档：不检测 / 尝试解密并检测（§1.4）三档：不检测 / 仅检测（识别加密，不尝试解密）/ 深度检测（尝试解密并扫描）以 demo 三档为准。
D-2方向切换配置按 receive/send/internal 三方向独立（§1、§5 上游依赖）数据模型按方向三份，但抽屉内无方向切换 UI，固定显示接收方向高影响，见 Q2。
D-3字段 Hover Tooltip§3 列出 10 条字段悬浮提示配置表单字段均无 Tooltip落地按 PRD 补齐。
D-4病毒库立即更新点击触发更新、按钮 loading、完成显示新版本（§3/§4）按钮无 onClick 绑定，点击无反馈落地需实现（依赖引擎状态 API，Q3）。
D-5保存模式「配置修改实时生效，无需手动保存按钮」（§3 批量操作）；另要求保存成功/失败 Toast抽屉底部有「保存配置」按钮 + 未保存提示，点击仅清标记、无 Toast正面冲突，见 Q1；以 demo 显式保存为倾向。
D-6非法输入修正数量输 0/负数（非-1）自动修正为 1；大小修正 1KB；超时修正 1 秒（§4）源码 parseInt||-1（个数/大小）与 ||1/||30（其余），输入 0 会被保留为 0，仅空串/非数字回退落地按 PRD 边界校验实现。
D-7密码本重复重复密码提示「密码已存在」不重复添加（§4）无重复校验，可加入相同密码；密码明文展示（PRD 要求安全管理员脱敏）落地补校验 + 脱敏。
D-8角色权限§1 权限矩阵（超管/安全管理员/审计员/普通用户）demo 无角色差异落地由网关 RBAC 承接。
D-9国际化§6 支持 zh/en/th；implement.md 要求四语抽屉宿主（Tab 标签/左导航/卡头/保存栏）与加密附件 Tab 硬编码中文，英文模式混排；语言切换不持久化；无第 4 语言落地统一 i18n key，见 Q6。
D-10抽屉头§2 示意「[←] 附件安全检测 + 启用开关」在标题栏标题栏为面包屑 + XCircle 关闭；启用开关在配置卡头低影响，以 demo 为准。
D-11响应式§2：≥1024 三列、768-1023 两列、<768 单列全屏抽屉Grid 列数固定（grid-cols-2/3），无断点降级落地按 PRD 补断点。
