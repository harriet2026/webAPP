4.3 可审计模块（AUDITABLE_FEATURE_IDS，27 个）

判定标准：页面上是否存在应被追责的敏感操作 —— 即使是查看类页面（统计报表导出、邮件调查放行/删除/召回）也纳入；纯浏览无敏感操作的页面（基础设施监控、引擎状态、只读日志）不计入。

5. 业务逻辑

5.1 过滤链路

baseLogs      按形态可见性裁剪（逐条 isLogAvailableInForm）
  ↓
scopedLogs    按 viewMode / 分层 Tab / 本租户裁剪
  ↓
filteredLogs  按筛选条件（多条件 AND）
  ↓
统计概览 + 列表

5.2 权限与形态

  • 平台视角：可见平台级操作 + 可下钻查看各租户的租户级操作（含「所属租户」列与租户范围筛选）。
  • 租户视角：仅可见本租户（currentTenant.id）的租户级操作，无分层 Tab、无租户列。
  • 单租户形态：无分层概念，展示全部管理员操作。
  • 同源裁剪：日志可见性与模块枚举都复用菜单权限 resolveAccess；锁定（🔒）模块不纳入枚举。

5.3 存储与防篡改（PRD 建议）

审计日志应只增不改不删（防篡改），建议独立存储并设保留周期与归档策略（具体天数 PRD 未给出）；before/after 变更快照需完整留存。列表查询建议服务端分页，P95 < 1s；导出走异步任务。demo 是内存全量切片的前端分页。

9. 与 spec 的差异标注

#差异点PRDdemo 实际建议
D13 处 hover 提示§3.1 建议：操作模块完整路径 / 来源 IP 归属地全称 / 操作摘要全文一个都没实现（无 title/Tooltip）落地补
D2来源 IP 不在列表列建议为 IP 列做 hover 提示IP 只在详情里，列表没有该列（但支持按 IP 搜索）列定义与交互建议不自洽 → §10 Q2
D3「变更对比」触发条件「修改类操作展示」代码判断是 before !== undefined || after !== undefined（与 opType 无关；grant/disable 带 before/after 也会显示，单边存在时另一侧显示「—」）明确条件
D4failReason 类型—自由文本（与认证日志的 7 类枚举不同），无标准化取值、无处置建议映射决定是否枚举化 → §10 Q1
D5无时间范围筛选 / 无排序 / 无导出PRD 未定义都没有审计场景标配；且本模块自己把「导出」列为可审计操作
D6服务端分页 / P95 / 留存归档「需求建议」内存全量切片接 /admin-audit 时补
D7layer 与 operatorRole 冗余—Mock 中二者恒等；「平台管理员代管某租户产生租户级操作」（operatorRole=platform, layer=tenant）这种情况 PRD 未定义如何呈现→ §10 Q4
D8切 Tab 重置筛选F1/TC2 刻意行为一致别当 bug 修

10. 需确认事项

#问题背景
Q1failReason 要不要枚举化？认证日志用 7 类枚举 + 处置建议映射；本页是自由文本，无法统计与联动
Q2列表要不要加「来源 IP」列？PRD 建议为 IP 列做 hover 提示，但列定义里根本没这一列
Q3要不要提供导出？本模块把「导出」列为可审计操作类型，自身却不提供导出；网关也无该端点
Q4「平台管理员代管租户产生租户级操作」如何呈现？operatorRole=platform + layer=tenant：租户 Tab 会把它算作租户级操作，但列表「操作者」列不显示层级徽标（徽标只在详情里）
Q5审计日志的保留周期与归档策略？PRD 只说「应设保留周期」，没给天数
Q6新增可审计模块时如何同步 AUDITABLE_FEATURE_IDS？模块枚举与菜单同源，但「哪些模块可审计」是手工维护的白名单 —— 新增功能页时容易漏
