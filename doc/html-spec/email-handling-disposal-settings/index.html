2.5 通知范围选择器（NotificationScopeSelector）

左右两栏：收信人组（来自「群组管理」，只读引用）+ 部门（来自「组织通讯录」的 deptPath 派生树，只读引用）。本页只消费，不新增/编辑组或部门。

元素行为
收信人组 · 搜索框占位符「搜索收信人组」，按名称大小写不敏感实时过滤
收信人组 · 列表ScrollArea h-44；每行 Checkbox + 组名 + 「N 人」；无匹配显示「无匹配结果」
部门 · 树ChevronRight 展开/折叠（旋转 90°）；勾选父节点 连带其全部子孙（getSelfAndDescendantPaths）；部分选中显示 半选态（indeterminate）；节点显示「(成员数)」+ 同步来源徽标（如「总部 AD」）
部门 · 搜索命中节点的全部祖先自动展开；无匹配显示「无匹配结果」
已选回显下方 Badge chips；组失效（源头被删）时显示红色「已失效」；部门 chips 后有「清空」按钮
空态无收信人组 → 「暂无收信人组，请先到「群组管理」创建」；通讯录未同步 → 「组织通讯录暂未同步，请先到「组织通讯录」配置数据源」
持久化存 id / path（recipientGroupIds: string[]、departmentPaths: string[]），不存名称

层级详情见 layer-2-notification-scope.html。

5.2 关键业务约束

  • 分数区间只作用于引擎概率检测；黑名单/规则等确定性命中（无置信度）始终通知，不受区间限制。
  • 通知范围存 id/path，源头对象被删除后 chip 显示「已失效」，不静默丢弃。
  • 「重置」把三个 Tab 全部恢复默认（无确认弹窗），「保存」一次性提交三个 Tab。
  • 用户权限的「有效天数」在开关关闭时禁用而非隐藏，保留原值。

10. 需确认事项

#问题背景影响
Q1通知频率「自定义」到底自定义什么？demo 选 custom 后 UI 无任何变化；网关模型有 custom_weekdays []int需要补一个星期多选控件，还是把 custom 去掉只留 daily/never？
Q2通知范围（收信人组 + 部门）要不要落地？网关模型目前没有这两个字段demo 做得很完整（树形/半选/失效态），但 DisposalQuarantineSettings 里没有 recipient_group_ids / department_paths要落地就必须给网关模型加字段 + DB 列（属于「新增字段」，按 implement.md 第 4 条需你确认）
Q3PRD 的三角色（超级管理员/安全管理员/审计员）如何映射到网关 RBAC（system_admin / tenant_admin）？「安全管理员只能改通知设置」这种字段级权限网关目前没有要么放弃字段级权限（全部按 admin 可写），要么新增角色 + 字段级 ACL
Q4网关已有但 UI 没有入口的字段是否要补 UI？portal_base_url（不配则隔离通知信里不带取回/预览链接，GT-12077）、max_recheck_minutes、timeout_temp_disposal / timeout_mark_*、tzportal_base_url 尤其关键：没有 UI 入口 → 租户无法自助配置 → 隔离通知信功能残缺
Q5置信度区间（min/max）要不要落到网关？网关 category_notify 只有 map[string]bool要支持 demo 的按分数区间通知，需把该字段升级为 map[string]{enabled,min,max}（DB 不兼容升级 —— 按项目约定可 drop & recreate）
Q6「保存设置」是否需要脏值检测与二次确认？demo 的「重置」直接清空三个 Tab 的改动，无确认弹窗误点「重置」会丢失全部未保存改动
