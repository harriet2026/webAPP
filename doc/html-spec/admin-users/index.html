0. 本版本变动（v4） 本次重点

v4 承接本轮会话中对「管理员账号」与「角色权限」两个 Tab 的 6 项对齐/修复诉求。以下逐项列出变动点、根因与验证证据；对应界面证据见 §4 截图式交互预览。

#变动点变动前变动后根因/实现源码证据
CH-1 账号状态下拉可选 新建/编辑抽屉「账号状态」硬编码 disabled（只读） 新建与编辑均可自由选择「启用（正常）/停用」；编辑改为停用时经 setUserStatus/setTenantUserStatus 提交（停用同时终止在线会话） 解锁 Select、绑定表单 status 字段；CreateUserRequest 增补 status users/page.tsx、lib/api/users.ts §4.3
CH-2 角色下拉可展开 Mock 未覆盖 GET /roles，dispatcher 兜底返回空列表 → 角色下拉无选项、点开为空（表现为“锁定”） 下拉可展开并含平台/租户内置角色选项 dispatcher 新增 GET /roles Mock（平台 3 + 租户 3） lib/mock/dispatcher.ts §4.2
CH-3 抽屉排版与列表列对齐 抽屉用描边卡片 + h4 分区；字段序为 姓名→手机号→邮箱；间距 space-y-4/1.5 改用「下划线分区标题」规范（与角色抽屉一致）；字段序改为 姓名→邮箱→手机号（对齐列表列序）；间距 space-y-5/2；宽度保持 max-w-xl（576px） 对齐 RoleDrawer 的 shell 规范 users/page.tsx §4.2

1.1 内置角色作用域差异（CH-6 新增关注点）

「角色权限」Tab 的内置角色随视角作用域（scope）不同而不同——这是本轮明确的核心语义：

视角scope内置角色（Mock 种子）权限矩阵覆盖模块验证
平台管理员platform 超级管理员（系统默认）/ 平台运维管理员 / 平台审计员 系统状态、监控中心、统计报表、邮件处置、日志审计、系统管理、管理员与权限（含平台专属：代理服务器/DKIM/密码策略等） 浏览器实测（§4.4、§4.5）
租户管理员tenant 租户管理员（系统默认）/ 租户操作员 / 租户观察员 由 rbacSubmodulesForScope('tenant') 返回的租户专属模块（如 策略流水线/群组策略/智能体管理），与平台集合不相同 列表 scope 过滤逻辑已验证；租户代登录视角截图无法安全触发（见 Q-010）

2. 功能概述

「管理员与权限」统一管理平台管理员账号、角色权限与登录安全策略，由三个 Tab 组成。本页在平台/租户双视角下按作用域隔离。

Tab说明对应区域/状态本轮是否变动
管理员账号管理员 CRUD、重置密码、强制下线、批量操作；账号状态启停§4.1、§4.2、§4.3是（CH-1/2/3/4/5）
角色权限角色列表 + 三级 RBAC 权限矩阵（模块可见 × view/edit/approve/delete）；内置角色只读查看、自定义角色编辑/删除§4.4、§4.5是（CH-2/6）
登录安全密码策略/登录控制/IP 访问控制/单点登录 + 租户基线加严 + 二次认证§4.6否（本轮未改）
