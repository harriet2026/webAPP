4. 数据模型与 API 映射

interface ContentRule {
  id: string                       // CR-YYYYMMDD-NNN
  name: string
  priority: number                 // demo 表单范围 1-9999，默认 100
  matchType: "keyword" | "regex" | "content_group"
  matchContent: string             // 关键词用 | 分隔 / JS 正则 / 内容组名称
  scopes: ScopeType[]              // subject | body | header | attachment_name | attachment_content
  directions: {                    // 每方向独立启用位 + 动作
    receive: DirectionAction
    send: DirectionAction
    internal: DirectionAction
  }
  enabled: boolean
  expiresAt?: string               // 缺省=永久；过期→「已过期」，7天内→「即将到期」
  remark?: string                  // ≤200字
  createdAt: string
  updatedAt: string
}
interface DirectionAction {
  enabled: boolean
  action: "block" | "block_alert" | "isolate" | "review" | "mark"
  tag?: string                     // mark 动作的标记文本（如 "[广告]"），仅存在于 mock 数据，编辑抽屉无对应输入
  notifyAdmin?: boolean            // 仅 mock 数据，UI 未渲染
  notifySender?: boolean           // 仅 mock 数据，UI 未渲染
}
PRD API / 数据表用途落地映射建议需确认
GET/POST/PUT/DELETE /api/v1/security-policy/rules（0708 PRD §5.4）规则 CRUD、分页、搜索、状态筛选复用统一规则系统 CRUD，page=content-rules（或等价 policy_key=content）区分功能页；方向（接收/外发/域内）映射统一规则的 direction 维度。统一规则系统是否支持「一条规则三方向各自独立动作」，或需拆为 3 条底层规则（见 Q5）。
POST /api/v1/security-policy/test（PRD F7 命中测试）模拟测试demo 为前端本地匹配（RegExp / includes）；落地若要真实链路需统一规则 dry-run 接口。是否新增 dry-run API。
内容组（content_group）匹配类型第三项「内容组」引用预定义关键词集合对应 PRD §5.1 全局对象库「内容组」；demo 中仅为文本输入，无选择器。内容组数据源与选择 UI（Q1）。
security_policy_rule 表（PRD §5.4）id, rule_id, rule_name, policy_key, stage, action, config(json), priority, enabled, version, tenant_id, scopematchType/matchContent/scopes/directions 入 config JSON；policy_key=content, stage=3。非硬性要求；若统一规则系统已有表结构则不新建。
批量导入/导出工具栏按钮demo 无实现；PRD 未定义格式。格式（CSV/JSON）与 API（Q8）。

9. 与 PRD / 源码 / 浏览器渲染的差异标注

#差异点spec/PRD 描述demo 实际建议处理
D1阶段3子策略数量策略流水线需求文档：阶段3内容层「3个子策略」（附件安全、URL防护、内容规则）demo 阶段3 有 4 张卡：附件安全检测、URL检测与防护、内容规则、意图引擎（0708 PRD §1.3 流程图亦含意图引擎）以 demo/0708 PRD 为准，策略流水线文档未更新。
D2优先级语义自相矛盾0708 PRD：数字越小越先匹配；网关统一规则系统：数值越大越优先列表按数值降序排序 + 配置提示「数值越大优先级越高」，但编辑抽屉优先级 Tooltip 与 hint 写「数值越小优先级越高」落地统一为「数值越大越优先」（网关定义），修正抽屉文案。
D3应用配置示例不清除正则错误—（spec 未覆盖）浏览器实测：先输入非法正则触发错误，再点示例「应用」填入合法正则 \d{17}[\dXx]，红字「正则表达式语法错误，请检查」与红框仍残留（applyExample 未重算 regexError），且该残留错误会让保存校验失败落地需在应用示例时重新校验/清除 regexError。
D4校验时机策略流水线需求文档：名称为空则「保存按钮置灰」；PRD §4.1 规则名 1–50 字符、禁 < > & "、重名拦截保存按钮始终可点，点击后才显示红字；无长度/字符/重名校验以 demo 交互为准（点击后显红字），但长度/字符/重名校验需落地补齐。
D5批量操作范围PRD §3.4：批量启用/禁用/删除 + 跨页选 + 部分成功反馈仅批量删除；全选只作用当前页；无部分成功弹窗需确认是否补批量启停与跨页选。
D6优先级列与拖拽排序PRD F2：列表支持拖拽排序；D区含优先级列列表无优先级列、无拖拽手柄，优先级仅在编辑抽屉数字输入需确认列表是否补优先级列/拖拽。
D7导入/导出无实现PRD 数据迁移支持 JSON 导入/导出批量导入、导出按钮无任何点击处理需确认格式与交互后补齐。
D8抽屉尺寸策略流水线需求文档：配置抽屉固定 480px；0708 PRD：创建/编辑抽屉 640px内容策略抽屉 80vw、规则编辑抽屉 920px以 demo 为准记录。
D9行点击详情0708 PRD §3.2：点击数据行打开只读详情抽屉（480px）行点击无反应，仅编辑图标/菜单可操作需确认是否要只读详情态。
D10per-direction 动作 vs 统一动作—（spec 未覆盖）数据模型支持三方向独立 action/tag/notify*（mock 数据有体现），编辑抽屉只提供一个统一动作下拉（应用于所有勾选方向）；mark 的 tag、notifyAdmin/notifySender 无编辑入口编辑能力弱于数据模型，落地取舍见 Q5。
D11i18n 硬编码implement.md 四语要求行内菜单（禁用/启用/复制规则/删除）、编辑 Tooltip「编辑」、formatDate(zh-CN)/「永久」硬编码中文；仅 zh/en/th 三语落地统一走 i18n 资源，补第4语言（Q7）。
D12保存无持久化PRD：保存成功 Toast、配置 30s 内生效「保存配置」仅清除前端脏标记；规则 CRUD 仅内存 state，刷新即失；无 Toastdemo 原型限制，落地接统一规则系统 API。
